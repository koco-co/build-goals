# 设计方案与确认门禁

本阶段把调研结论和已确认决策转化为可实施设计。用户明确确认前，目标仓库保持只读。

## Phase 1：定义行为契约

设计方案必须说明：

- Outcome：一句话结果；
- Routing：独立输入分支和不属于本 Skill 的处理；
- Inputs：每个分支需要什么；
- Outputs：产物、格式、命名和位置；
- Workflow：阶段、分支、失败路径和完成条件；
- Side effects：会修改什么，哪些操作需另行授权；
- Guardrails：数据、权限、接口和范围边界；
- Acceptance：机械检查、内容审查、文案审查和真实场景。

## Phase 2：设计 Frontmatter

完整读取 `rules/frontmatter.md`，为新建和已有 Skill 都输出字段决策矩阵：

| 字段或配置 | 是否添加 | 目标平台 | 判断依据 |
| ---------- | -------- | -------- | -------- |
| `name` | 是 | 通用 | 必填 |

矩阵必须逐字段覆盖调用方式、触发路径、参数提示、命名参数、工具授权与禁用、上下文、Agent、前台等待、模型、推理强度、Hooks、Shell、环境要求、许可证、元数据和 `agents/openai.yaml`。每个能够独立省略的字段单独判断；只有 `name` 与 `description` 的现有 Skill 也不得跳过。

## Phase 3：设计最小充分目录

先根据内容职责选择目录，再展示 `tree`。目录选择规则见 `rules/architecture.md`。

每个拟创建的文件都要回答：

1. 它解决什么独立问题；
2. 何时读取或执行；
3. 为什么不能合并到现有文件；
4. 如何验证它有用；
5. 谁是该规则或结构的唯一规范源。

无法回答时，不创建该文件或目录。

## Phase 4：画出按需读取关系

使用表格或流程表达：

| 条件           | 读取或执行                | 用途           | 完成信号       |
| -------------- | ------------------------- | -------------- | -------------- |
| 输入属于分支 A | `workflows/a.md`          | 执行 A 流程    | A 产物通过检查 |
| 生成固定产物   | `templates/x.template.md` | 固定结构       | 必填字段齐全   |
| 需要输出范式   | `examples/x.example.md`   | 模仿粒度与风格 | 内容与文案审查通过 |
| 完成实现       | `scripts/validate.py`     | 机械检查       | 退出码为 0     |

禁止默认一次性读取全部附属文件。

## Phase 5：划分 Skill、脚本、CLI 与 Hooks

将能力放入最可靠的位置：

- 已有仓库 CLI 能完成：复用 CLI；
- 可确定性执行：脚本或测试；
- 每次事件都必须自动发生：Hooks 或 CI；
- 固定输出结构：模板；
- 输出范式：Few-shot 示例；
- 复杂判断和阶段编排：工作流；
- 无法机械判断的约束：规则或清单。

建议放在 Skill 目录外的能力必须说明：建议位置、触发时机、输入输出、与现有行为的关系，以及是否需要额外授权。

## Phase 6：设计平台适配

按照 `rules/platform-compatibility.md`：

- 保留一份平台中立的核心工作流；
- 只为真实差异增加适配层；
- 不把一个平台的专属字段直接假定为另一个平台支持；
- 明确哪些平台可以真实运行验证，哪些只能静态检查。

## Phase 7：设计审查流程

明确：

- 内容审查使用 `checklists/content-review.md`；
- 文案审查使用 `checklists/copy-review.md`，需要示范时读取 `examples/copy-review.example.md`；
- 文案修改后的内容回归范围；
- 是否属于必须调用独立 Reviewer 的重要变更；
- 无法调用独立 Agent 时如何记录降级。

## Phase 8：提交设计方案

使用 `templates/design-proposal.template.md`，至少包含：

1. 调研结论；
2. 已确认决策；
3. 目标与非目标；
4. 输入、输出和路由；
5. Frontmatter 字段决策矩阵；
6. 推荐目录树及职责；
7. 按需读取关系；
8. CLI、脚本、Hooks 和 Skill 的边界；
9. 平台适配；
10. 内容审查、文案审查和独立审查安排；
11. 实施范围；
12. 验收标准；
13. 风险与迁移说明。

最后只提出一次确认：是否按照该方案开始实施。

用户没有明确确认时，继续调整方案，不修改目标文件。
