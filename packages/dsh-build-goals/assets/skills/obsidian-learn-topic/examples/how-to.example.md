# 操作指南样例：定位 Locator strictness 失败

> [!abstract] 要完成的任务
> 找出一个 Locator 为什么匹配多个元素，并把修复限定在真实业务边界内。

## 适用条件

测试已经能稳定复现 strictness 错误，且读者已经掌握基本 Locator 语义。本指南不负责从零教授 Locator。

## 操作前检查

- 保存完整错误信息与匹配候选，不只截取最后一行。
- 确认页面数据和用户身份与失败场景一致。
- 确认没有使用会改变页面状态的并发调试操作。

## 操作步骤

1. 从错误信息列出的候选元素确认“多个匹配”是否符合真实页面状态。
2. 写出目标的业务边界，例如“订单详情区域内的取消按钮”。
3. 先限定能被用户识别的容器，再在容器内使用角色与名称定位目标。
4. 重新运行原测试，确认匹配数量和最终业务断言。
5. 再运行一个包含相似按钮的变式场景，证明修复不是偶然唯一。

## 成功验证

- 原失败场景通过。
- 相似目标仍存在时 Locator 只匹配业务目标。
- 最终业务断言证明点击结果，而不只证明点击动作没有抛错。

## 故障处理

| 现象 | 更可能的原因 | 下一步 |
| --- | --- | --- |
| 仍匹配多个目标 | 容器本身不唯一 | 回到业务边界，检查容器的名称或所属数据 |
| 变成零匹配 | 名称或状态随数据变化 | 核对测试数据与页面可访问名称 |
| 点击成功但业务断言失败 | 定位已修复，业务状态仍错误 | 转入业务流程或数据问题排查 |

## 不适用场景

页面只在 CI 中超时但本地 Locator 始终唯一时，本指南不足以判断根因；应转入 trace、网络、数据或环境隔离诊断。

## 来源与版本

运行时必须重新核验当前官方 Locator 严格性文档；本文件只示范操作指南结构。
