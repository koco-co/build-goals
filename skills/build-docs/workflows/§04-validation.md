# 验证与交付

## 文件与引用

按已确认路径映射逐项检查：本批文件已写入，保留项未被覆盖，从引用所在文档的目录解析跨组链接，确认路径和章节实际存在。整套完成时全部 12 类职责都有对应内容，ADR 无记录时有明确说明；中途批次允许索引保留“待建立”。

检查 AGENTS.md 中只有一个相关入口，描述为一行，相对路径可定位到实际 Brief。审阅 Diff，确认没有修改产品代码、机器 Schema 或其他未授权文件；Git 项目执行 `git diff --check`。

优先运行项目已有的 Markdown Lint、文档构建和链接检查命令。没有现成工具时直接核对实际文件和章节，不为文档任务安装新工具或新建验证框架。

## 内容与证据

使用 `checklists/acceptance.md` 检查业务契约、依赖顺序、现状证据及跨文档一致性，再检查文案和术语。修改表达后复查受影响的内容，避免把“计划”“已实现”改成“已完成”。

ENVIRONMENT_SETUP 中的命令区分已定义、已运行和待实现。只有在本次授权范围及环境允许时执行现有命令，安装依赖、迁移数据或部署不属于文档任务。未运行命令和未做的客户端行为检查明确标为未验证；静态提取不等于项目测试通过。

发现问题时修正文档并重新检查受影响项；若修复需要新的设计选择或超出本批范围，先更新预览并确认。

## 交付

简短报告实际新增或更新的文档、AGENT_BRIEF 入口、检查结果、未验证项和剩余批次。区分“文档已整理”和“产品已完成”，不执行后续开发，也不将文档中的下一步自动变成当前任务。
