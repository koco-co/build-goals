# 设计落实检查清单

本清单用于比较“已确认设计”和“最终实现”，不替代机械校验。

## 目标与范围

- [ ] 每个已确认目标都有对应实现或明确证据。
- [ ] 每个明确非目标都没有被意外纳入。
- [ ] 变更没有越过用户确认的路径和行为范围。
- [ ] 提交、推送、发布和破坏性操作均有独立授权。

## 路由与流程

- [ ] Outcome 能用一句话说明最终结果。
- [ ] 每个独立输入都能路由到唯一分支。
- [ ] 相邻但不属于本 Skill 的任务有明确退出方式。
- [ ] 每个阶段都有完成条件。
- [ ] 失败、阻塞和用户取消都有可预期结果。
- [ ] 用户确认前保持只读。

## 架构

- [ ] 每个目录和文件都有单一、必要职责。
- [ ] 没有空目录、空文件或未来占位内容。
- [ ] `SKILL.md` 保持主流程清晰，细节按需读取。
- [ ] 模板、示例、规则、工作流和 References 没有重复职责。
- [ ] 可确定性执行的内容已交给 CLI、脚本或测试。
- [ ] 每次事件必须自动发生的内容已放入 Hooks 或 CI。
- [ ] 项目级 Skill 复用了项目已有能力，没有复制业务实现。

## 平台适配

- [ ] 核心工作流只有一个规范源。
- [ ] 平台专属字段没有污染其他平台配置。
- [ ] 显式与隐式调用策略符合用户要求。
- [ ] 安装路径、权限和依赖符合目标平台当前契约。
- [ ] 无法等价适配的能力已明确降级。

## 验收设计

- [ ] 机械检查、语义验收和真实场景彼此分离。
- [ ] 正向、负向和失败路径都有测试。
- [ ] 验证命令可复现，失败返回非零退出码。
- [ ] 未验证与阻塞项不会被描述为已通过。
