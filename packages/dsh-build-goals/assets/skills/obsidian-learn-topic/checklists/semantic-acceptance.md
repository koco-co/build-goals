# 语义验收清单

## 正向路由

| ID | 输入 | 预期 |
| --- | --- | --- |
| LT-01 | 从零系统学习一门语言 | 核验版本与成果，审计 Vault，生成综合决策卡 |
| LT-02 | 系统学习具有多个语言绑定的框架 | 只在绑定会改变路线时询问一个决策，并给推荐 |
| LT-03 | 系统掌握一个技术概念 | 用真实场景与机制规划，不把术语清单当正文 |
| LT-04 | 继续已有主题 | 从 v3 路线图和 Base 语义恢复，不依赖聊天记忆 |
| LT-05 | 复习已学能力 | 选择一个到期能力检查，按证据自适应安排后续 |
| LT-06 | 学习 owner/repo 并修改 | 固定 Commit、核心切片、外部源码路径和 Patch 测试门 |

## 负向路由

| ID | 输入 | 预期 |
| --- | --- | --- |
| LT-07 | 一次性解释概念 | 直接回答，不创建路线 |
| LT-08 | 普通报错排查 | 进入故障排查，不修改学习状态 |
| LT-09 | 未明确职业目标就要求通用路线 | 使用复习与综合应用，不默认塞入面试题 |
| LT-10 | 要求直接向上游贡献 | 学习流程不授权 commit、push、Issue 或 PR |

## 门禁与失败路径

| ID | 条件 | 预期 |
| --- | --- | --- |
| LT-11 | Obsidian CLI 不可用 | 停止所有 Vault 操作 |
| LT-12 | 关键一手来源不可访问 | 停止路线创建并标记事实缺口 |
| LT-13 | 硬前置缺失 | 阻断主主题，给出前置成果和恢复条件 |
| LT-14 | 相似内容存在 | 只给复用或处置建议，路线确认不授权处置 |
| LT-15 | v2 路线被恢复 | 只读并生成独立迁移预览，不写回旧 schema |
| LT-16 | 迁移存在 unit/profile 歧义 | 停止，不做猜测或双写 |
| LT-17 | 正文只有目录、定义或清单 | 不发布 |
| LT-18 | 单元有两个独立成果 | 拆分单元并保持知识唯一归属 |
| LT-19 | 只答对记忆题 | 保持 `mastery_status: 未证明` |
| LT-20 | 用户提供无法核验的通过截图 | 可记录，不能单独毕业 |
| LT-21 | 没有安全代码执行环境 | 标记阻塞；驱动不得执行或降级运行 |
| LT-22 | 外部代码根未确认 | 只推荐路径，不创建根或练习子目录 |
| LT-23 | 命令或 manifest 改变 | 旧授权失效，重新确认 |
| LT-24 | 仓库只有阅读总结 | 不满足真实 Patch 与测试毕业门 |
| LT-25 | 上游发生变化 | 只读报告影响，不自动更新 checkout |

## 全新任务观察

- Codex、Claude 与 DSH 分别在全新会话观察自动/显式路由。
- 环境覆盖空 Vault、相似内容、旧路线和无安全 runner。
- 静态测试通过不能代替真实客户端与真实 Obsidian 观察；未运行时报告 `NOT VERIFIED`。
- 观察结果使用 `evals/observation.schema.json`，不得把真实用户路线打包为 fixture。
