# 平台与作用域规则

## 单一来源

- 每个指令作用域以 `AGENTS.md` 为唯一正文。
- 同目录 `CLAUDE.md` 首选相对符号链接，目标必须精确为 `AGENTS.md`。
- 不使用绝对链接、跨目录链接或两份同步维护的正文。
- 无法可靠保存符号链接的平台可使用仅含 `@AGENTS.md` 的普通文件作为兼容回退；必须在预览与交付中标明。用户要求符号链接时，回退不算通过。

创建后同时检查链接文本和解析目标。Git 仓库还应确认索引模式为 `120000`，避免符号链接在提交前被意外展开为普通文件。

## Claude 专有内容迁移

读取现有 `CLAUDE.md` 后逐条归类：

1. 能跨平台表达的项目规则：泛化措辞后迁入 `AGENTS.md`。
2. 只与 Claude Code 机制有关、但不会伤害 Codex 的提示：改写为带条件的平台说明。
3. 与单一正文目标冲突或无法安全泛化的规则：在完整替换预览中列出影响，请用户决定保留例外还是移除。

不得静默丢失 Claude 专有行为，也不得把 Claude Code 的全局配置误写成项目事实。

## 作用域与优先级

根 `AGENTS.md` 描述全仓库共同事实。嵌套 `AGENTS.md` 只补充其目录树的差异；遇到冲突时，表述必须明确嵌套规则在该子树内覆盖根规则。

预览中为每个嵌套文件写出创建理由。理由消失时应删除该嵌套文件及其同目录 `CLAUDE.md`，而不是留下重复或过期说明。

## 允许写入的项目文件

本 Skill 的运行时写入范围仅为已确认位置的 `AGENTS.md` 与 `CLAUDE.md`。不得创建项目级 `docs/`、格式化器、lint、CI、测试 harness、安装脚本或示例工程。

若研究发现这些体系缺失，只把它们列为现状或后续建议；没有额外授权，不把建议变成本次修改。

## 外部动作

写入指令不自动授权安装依赖、访问外部服务、提交、推送、发布或更新本地 Plugin。实现和验证完成后，统一询问一次当前项目实际适用的动作；用户只批准其中一项时，不推导其他授权。
