# 调研与环境探索

本阶段建立事实基线。除非用户已经明确授权并且任务处于实施阶段，否则只执行读取、搜索、分析和无副作用验证。

## Phase 1：确认调用与任务边界

1. 确认用户明确调用了 `building-skills`。
2. 判断任务属于以下哪一类：
   - 新建通用 Skill；
   - 新建项目级定制 Skill；
   - 审查并升级已有 Skill。
3. 从现有输入中提取：目标、非目标、目标平台、输入、输出、已知分支、交付位置和用户已经给出的决策。
4. 记录当前授权范围。设计确认、文件修改、提交、推送和发布是彼此独立的授权，不得相互推定。

## Phase 2：检查当前环境

对 Skills 仓库至少检查：

- 目录布局和命名规则；
- 已有 Skills 的组织方式；
- 平台适配和安装方式；
- CLI、脚本、测试、Hooks、模板和公共组件；
- Frontmatter 与文档规范；
- 加载、触发、验证和发布方式；
- 是否已有能够复用的构建或校验能力。

对项目级 Skill 还要检查：

- 代码架构和技术栈；
- 构建、测试、发布和 CI 入口；
- 项目内规则、知识库和文档；
- 已有 CLI、Lint、格式化、代码生成和校验机制；
- 与目标 Skill 相关的真实业务流程；
- Skill 应放置的位置及其与项目能力的边界。

对已有 Skill 还要建立基线：

- 当前支持的输入和输出；
- 当前路由、工作流和副作用；
- 已被外部依赖的文件、命令或接口；
- 可复现的问题与已有测试；
- 哪些内容必须兼容，哪些内容允许重构。

## Phase 3：核对平台契约与同类实现

1. 优先读取目标平台当前官方规范，确认目录、Frontmatter、触发、权限和资源读取机制。
2. 调研同类 Skill、插件或工具，比较其路由、澄清、工作流、模板、校验、用户确认和平台兼容方式。
3. 只借鉴能够改善当前设计的机制，不机械复制目录或措辞。
4. 记录外部来源、许可证和实际借鉴点；来源或许可证不清楚的内容不得复制。
5. 用户明确免除外部竞品调研时，可以跳过第 2 至 4 项，但不得跳过目标环境和平台契约核对。

## Phase 4：形成调研摘要

输出一份内部工作摘要，至少包含：

```text
任务类型：
已确认目标：
明确非目标：
目标平台：
现有可复用能力：
现有约束与兼容接口：
同类实现可借鉴点：
外部来源与许可证：
事实：
推断：
未知项：
潜在风险：
```

完成标准：后续所有关键问题都能追溯到真实未知项，而不是因为没有检查环境而产生。
