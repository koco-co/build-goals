# 平台与目录范围

## 统一维护

- 每个目录范围内的正文统一维护在 `AGENTS.md`。
- 同目录 `CLAUDE.md` 必须是普通文件，内容精确为 `@AGENTS.md`。

单一来源、导入内容与普通文件类型由 `validate_agents_md.py` 硬性检查，本文件只讲脚本判断题之外的决策：何时建立嵌套文件、既有 `CLAUDE.md` 内容如何迁移、可修改文件范围。

## Claude 专有内容迁移

读取现有 `CLAUDE.md` 后逐条归类：

1. 能跨平台表达的项目规则：泛化措辞后迁入 `AGENTS.md`。
2. 只与 Claude Code 机制有关、但不会伤害 Codex 的提示：改写为带条件的平台说明。
3. 无法安全改写为公共规则的内容：在完整内容预览中说明影响，请用户决定保留例外还是移除。

不得静默丢失 Claude 专有行为，也不得把 Claude Code 的全局配置误写成项目事实。

## 目录范围与优先级

根 `AGENTS.md` 描述全仓库共同事实。嵌套 `AGENTS.md` 只补充所在目录的差异；遇到冲突时，必须明确子目录规则在该目录内覆盖根规则。

预览中为每个嵌套文件写出创建理由。理由消失时应删除该嵌套文件及其同目录 `CLAUDE.md`，而不是留下重复或过期说明。

## 可以修改的文件

本 Skill 只能修改已确认位置的 `AGENTS.md` 与 `CLAUDE.md`。不得创建项目级 `docs/`、格式化器、lint、CI、测试 harness、安装脚本或示例工程。

若研究发现这些体系缺失，只把它们列为现状或后续建议；没有额外授权，不把建议变成本次修改。

## 后续操作

写入指令不自动授权安装依赖、访问外部服务、提交、推送、发布或更新本地 Plugin。实现和验证完成后，统一询问一次当前项目需要哪些后续操作；用户只批准其中一项时，不推导其他授权。
