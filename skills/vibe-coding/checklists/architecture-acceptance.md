# 架构方案验收清单

## 需求与事实

- [ ] PRD 路线的全部功能和验收 ID 已提取。
- [ ] 迁移路线的当前架构和高优先级 Findings 有文件或命令证据。
- [ ] 已确认事实、外部参考、推断和未知项彼此区分。
- [ ] 用户现有修改和稳定接口的保护方式明确。

## 调研

- [ ] 官方规范、竞品和活跃开源项目均有一手来源。
- [ ] 版本与维护状态按当前日期核对。
- [ ] 至少比较两个可行方案。
- [ ] 推荐不是由热度、个人偏好或“最新”单独决定。
- [ ] 外部代码、文案和资产的许可证边界清楚。

## 目标架构

- [ ] 技术栈与约束匹配，工具职责不重复。
- [ ] 目录树、模块职责和依赖方向清楚。
- [ ] 数据、API、事件、配置和错误契约明确。
- [ ] 安全、权限、秘密和隐私有设计。
- [ ] 测试数据、TDD、CI、E2E 和可选视觉验证有方案。
- [ ] 部署、可观测性、恢复和迁移边界适用。
- [ ] 主要权衡、风险、拒绝方案和停止条件明确。
- [ ] 每项需求或迁移目标能映射到架构组件。

## 确认门禁

- [ ] 方案只在对话中预览，确认前没有项目写入。
- [ ] 用户已明确确认推荐架构和排除项。
- [ ] 架构文档写入后无 TODO、TBD、待确认或模板占位。
