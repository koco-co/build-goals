# GitHub README 风格

使用标准 GitHub Flavored Markdown，优先保证信息准确、层级清楚、命令可复制和移动端可读。视觉形式服务于内容，不强制居中 HTML、花体 Unicode、固定徽章数量或中英文字形差异。

## 内容层级

- 首个非空行使用一个清楚的一级标题；后续章节按内容需要组织。
- 首屏尽快说明项目用途、目标用户和首次成功路径。
- 粗体、斜体、引用和折叠块按普通 Markdown 语义使用，不把样式本身当作验收目标。
- 表格只用于有重复字段或明确映射的内容；过宽表格改为列表或拆表。

## 徽章、图表与图片

- 徽章只展示仓库中可核实的版本、构建、覆盖率或许可证状态；没有信息价值时可以不放。
- Mermaid 只表达真实流程、依赖、状态或组件关系，不为装饰而创建。
- 图片必须帮助理解产品或流程，并提供具体替代文本。优先使用仓库内、授权明确的资源；远程图片必须来源稳定且与内容相关。
- SVG 必须是有效 XML，不得包含脚本、事件处理器、外部资源或脚本 URL。

## 可验证性

`scripts/validate_readme.py --strict` 只检查可客观判断的结构和安全问题：一级标题、未替换占位符、代码围栏语言与闭合、HTML 配对、本地引用范围与存在性、图片替代文本、SVG 安全和基本 Mermaid 声明。它不规定品牌审美。

远程链接仅在显式使用 `--verify-remote` 时联网检查。静态校验不能证明链接内容、安装步骤或客户端行为正确，这些结论仍需按项目证据或真实运行结果验收。
