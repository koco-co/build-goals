# 渐进式迁移任务示例

本示例展示如何把架构问题切成 `docs/实施任务/功能域/<功能域>.md` 中可独立验证的迁移单元。

## Finding

`AUD-004`：配置从多个模块读取环境变量并使用不同默认值，导致测试、CLI 和服务启动行为不一致。

## 任务

### TASK-011 统一 Typed Configuration 边界

- Finding：AUD-004
- 目标：所有运行入口通过一个 typed settings 模块读取配置；缺少必填项时在启动阶段给出一致错误。
- 行为保持：现有环境变量名继续兼容一个迁移周期。
- 允许修改：`src/config/`、各入口配置装配、相关测试、`.env.example`
- 禁止修改：业务领域规则、公开 API 响应。
- 第一条失败测试：CLI 与服务入口对同一无效配置返回相同错误码和用户文案。
- Characterization test：记录旧变量名和当前有效默认值。
- 正常测试数据：隔离临时环境变量集合。
- 依赖：无
- 并行：不可与锁文件升级任务并行，因为都修改启动配置。
- 提交边界：配置模块、兼容映射、入口接入、测试和示例配置一次提交。
- 回滚：revert commit；旧变量读取路径保留在前一提交。
- 完成条件：格式、类型、单元、入口集成和秘密检查通过。

迁移任务以可观察行为和兼容性为边界，而不是“重构 config 文件”这种不可验收描述。

如果该迁移改变了启动、配置或测试命令，项目指令就绪任务必须依赖本任务；完成命令验证和必要的 `build-agents-md` 更新并通过 readiness 后，才创建后续功能 worktree。
