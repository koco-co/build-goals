# 学习证据合同

每个可学习单元对应一份独立学习记录。正文和学习记录通过 Wikilink 与相同 `unit_id` 双向关联。

## 记录位置与职责

- 学习记录统一放在路线最后一个连续编号的 `NN-学习记录/`，文件使用 `§NN-<单元>-学习记录.md`。
- 使用 `templates/learning-record.template.md`，`record_type: learning-evidence`。
- 课程路线图不创建学习记录；每篇已创建知识正文恰好对应一份学习记录。
- 正文保存稳定知识，学习记录保存知识点状态、问题、用户原始回答、评定、练习证据、薄弱点和复习历史。

## 强制事务顺序

1. 用 Obsidian CLI 读取知识正文、对应学习记录和精确快照。
2. 依据课程路线图确认当前 `unit_id`、单项成果和通过标准。
3. 新单元先创建正文并读回，再创建对应学习记录并读回；任一步失败都不开始教学。
4. 在学习记录写入一道待回答题，通过 `roadmap_cli.py write-note` compare-and-swap 更新并读回。
5. 只向用户发送当前一道题，随后立即停止本轮。
6. 用户回答后，把原始回答、结论、原因/遗漏、下一步和证据写回学习记录，再读回。

没有完成第 3 步不得教学；没有完成第 6 步不得进入下一题或下一单元。

## 知识点与掌握状态

- `knowledge_points_total`：本单元需要验收的知识点总数。
- `knowledge_points_covered`：已有用户证据支持的数量。
- `knowledge_points_pending`：仍待回答或补测的数量。
- 三者满足 `covered + pending = total`。

题目状态至少区分 `待回答`、`已通过`、`需补充`。参考答案只能帮助补充，不能代替用户自己的解释或实践证据。

只有以下条件全部满足，学习记录才能设为 `learning_status: 已掌握`：

- 对应正文 `status: 已发布` 且 `coverage_status: 完整`；
- 所有必需知识点已通过；
- 分类毕业证据有效；
- `mastery_evidence`、`assessment_type`、`assessment_at` 和复习日期已写回。

## 分类毕业证据

- 原理解释：用户用自己的话解释机制，并分析一个新场景。
- 教程：用户独立复现并修改贯穿案例。
- 操作指南：用户完成真实任务并验证结果。
- 参考资料：用户能查找并正确应用所需信息。
- 开源仓库：固定 Commit 上的真实最小 Patch 与相关测试通过。

## 提问与反馈

每次只发送：进度状态行、场景、问题、提示。问题只验证一个核心点。回答后用三句以内给出结论、原因/遗漏和下一步，然后先回写学习记录。

## 复习

首次掌握安排 `+1d`；第 1 次通过后 `+7d`；第 2 次通过后 `+30d`，之后按证据调整。复习题、结果和下一次日期继续追加到同一学习记录，不创建巨大路线总日志。
