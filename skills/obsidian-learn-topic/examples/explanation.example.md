# 原理解释样例：幂等性为什么不能只靠重试

> [!question] 核心问题
> 支付请求超时后，客户端不知道服务端是否已经扣款。直接重试为什么可能造成重复扣款？

## 心智模型

把网络想成一名可能丢回执、但不一定丢包的快递员。客户端没收到回执，只能说明“结果未知”，不能说明“服务端没执行”。幂等键给多次相同意图一个稳定身份，使服务端能够返回同一结果而不是再次执行副作用。

## 工作机制

正文沿着“接受意图 → 原子占位 → 执行业务 → 固化结果 → 重放结果”解释状态变化，并给出并发到达、第一次失败、结果过期三条分支。完整例子必须说明持久化边界和原子性来源。

## 错误心智模型

“HTTP 方法写成 PUT 就自动幂等”混淆了协议语义与实现保证；“请求体相同就视为同一请求”又忽略了两个合法相同订单。两种错误都用反例拆解。

## 迁移证据

给出消息消费而非支付的新场景，让学习者设计去重身份、结果保存和过期策略，并指出至少一个无法保证 exactly-once 的边界。
