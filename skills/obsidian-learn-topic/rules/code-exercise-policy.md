# 普通代码练习合同

本合同适用于普通技术路线中学习目标包含“编写、修改或运行代码”的单元。纯概念、架构判断和阅读型单元使用主动回忆或场景题，不为了形式强行创建代码包。GitHub 开源仓库的真实 Patch 仍只遵守 `rules/repository-learning-policy.md`。

## 单元粒度

- 每个代码型单元只有一个必做核心练习包；最多附加两个不阻断掌握的可选变式或挑战。
- 一个练习只验证一组紧密相关的能力。目标出现互不相干的技能时拆分单元，不把综合项目塞进每篇基础笔记。
- 阶段或路线收尾可以安排综合项目，但仍需单独列出公开验收标准。

## 外部工作区确认门

- 完整代码放在持久的 Vault 外工作区；Vault 只保存练习说明、证据摘要和关联 Wikilink，`99-assets` 不保存完整代码项目。
- 模型只能推荐工作区位置。用户必须提供并最终确认一个已经存在的绝对根路径；驱动不会默认、猜测或创建这个根目录。
- 根路径确认后，驱动只可在该根下创建已预览的 `NN-练习名/` 子目录。保留源码和尝试历史；归档或删除需要独立确认。
- 笔记和持久证据不得保存机器绝对路径，只保存 `exercise_id`、相对目录名和 `attempt_id`。

## 文件与顺序

- 每个练习目录使用两位数字前缀，例如 `01-locator-basics/`。
- 独立可执行脚本使用 `NN-名称.扩展名`，例如 `01-locator-basics.py`。
- 多文件、可导入或依赖生态约定的项目，只编号练习目录；内部保留 `exercise.py`、`test_exercise.py`、`conftest.py`、`pyproject.toml` 等生态名称。
- 笔记必须按实际执行顺序列出文件和命令。插入或重编号需先展示映射、命令和引用影响并等待确认。

## 用户先写与提示层级

- 模型可以创建 starter、公开测试和配置，但不得在首次尝试前写核心解答、答案文件或等价实现。
- 用户先完成真实尝试。失败后依次提供：①失败现象与对应知识点；②文件、函数或边界提示；③局部伪代码或最小片段。
- 只有用户明确索要完整答案，或已有可验证的真实尝试后，才可展示完整解法。
- 模型修改用户代码需要独立授权；修改前先固化当前尝试证据。模型代写后的通过结果不能单独作为用户掌握证据。

## 公开验收

- 尝试前公开核心测试、完整 argv、必要测试点、通过标准和评分规则；不使用隐藏测试或秘密扣分项。
- 尝试后可以增加变式或边界测试，但必须先完整展示，并作为新的已确认命令重新授权。
- 必需核心测试全部通过；可选挑战不阻断掌握。Lint、格式化和类型检查只在本单元学习目标明确包含它们时成为硬门。
- 用户还要解释关键实现、失败边界或取舍；偶然绿灯不等于掌握。评分规则按练习目标公开制定，不强制统一权重。

## Manifest 与尝试证据

每个包包含：

```text
NN-练习名/
  .learn-topic/
    manifest.json
    authorization.json
    evidence/
      attempt-01.json
  <starter 与公开测试>
```

- `manifest.json` 固定练习 ID、版本、文件范围、公开命令、运行时写入范围、清理范围、通过标准、评分规则、三级提示和可选挑战。
- `attempt-NN.json` 只追加不覆盖，记录 manifest hash、代码 hash、argv、退出码、状态、耗时、可解析的通过/失败数和时间；不保存依赖、完整日志、敏感环境或机器绝对路径。
- Obsidian 学习记录只写尝试摘要、关键失败、最终得分、`exercise_id` 与 `attempt_id`；知识正文不保存尝试流水账。
- 驱动不自动 `git init`、commit，也不覆盖旧尝试。

## 命令授权与执行

首次执行前完整展示并确认：相对 cwd、argv、显式环境、超时、可能写入文件和清理范围。确认由 `scripts/exercise_cli.py authorize` 固化；未授权命令不能 Apply。

- 同一 manifest、同一命令可以重复执行；manifest 或命令变化会使旧授权失效。
- 新命令、安装、联网、容器、仓库脚本、读取其他外部目录、账号或凭据都需要新的明确确认。
- 命令必须是 argv 数组，使用清洁环境且不经过 shell；敏感键和值不得写入 manifest。
- 执行必须进入可验证的写隔离：仅允许写 manifest 声明的运行时路径和独立临时 HOME；不能提供隔离时生成 `blocked` attempt 并停止，不降级为普通子进程。
- 外部工作区根、manifest、authorization、公开测试与既有 evidence 都要在运行前后核验；越界写入或元数据变化必须阻断，既有 evidence 恢复并保持逐字不变。
- 超时、崩溃、越界写入或未批准文件都记为失败或阻塞并停止。
- 自动清理只允许 manifest 列出的临时输出；源码、manifest 和尝试证据永不自动删除。

## 掌握门

机械测试通过只证明这一轮命令成功。只有同时满足以下条件，对应学习记录才可标记 `已掌握`：

1. 最新必需命令全部有通过证据；
2. 用户能解释关键实现与边界；
3. 证据来自用户真实尝试，而不是模型代写；
4. 对应知识正文达到发布与完整覆盖门槛，学习记录链接或记录对应 `exercise_id`、`attempt_id` 和评分结果。
