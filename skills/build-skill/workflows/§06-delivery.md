# 交付与停止

交付报告用于让用户快速判断实现是否完整、验证是否可信，以及下一步是否可以开始。

## Phase 1：汇总事实

从实际变更和命令结果中汇总：

- 完成目标与排除项；
- 最终目录树；
- 新增、修改、移动和删除的文件；
- 位于 Skill 目录外的 CLI、Hooks 或公共能力；
- 平台适配；
- Frontmatter 字段决策及最终状态；
- 内容审查、文案审查、内容回归和独立 Reviewer 结果；
- 验证命令、场景和结果；
- 外部来源与许可证；
- 风险、未验证项和阻塞项。

不得根据计划推断完成情况，必须以最终文件和实际结果为准。

## Phase 2：标记验证状态

统一使用：

- **已验证**：已有命令输出、测试、文件或真实业务结果支撑；
- **未验证**：实现已完成，但当前环境无法真实运行或证据不足；
- **阻塞**：缺少权限、环境、输入或外部条件，无法继续完成。

“已创建文件”“静态阅读正常”和“应该可以运行”不等于“已验证”。

## Phase 3：生成报告

使用 `templates/delivery-report.template.md`。报告应让用户能够：

1. 定位所有变更；
2. 复现全部验证；
3. 了解平台差异；
4. 判断是否存在遗留风险；
5. 明确当前任务是否已经结束。

## Phase 4：按调用模式交付并停止

先判断本次是独立调用，还是由 `build-plugin` 等其他 Skill 统筹并调用。两种模式都必须先完成事实汇总、验证状态和交付报告，不得因任务由其他 Skill 统筹而省略内容审查、文案审查或验证。

### 受控调用（由上层 Skill 统筹）

- 不重复询问 commit、push、发布、独立安装或 Plugin 更新，也不自行执行；
- 向统筹本次任务的 Skill 返回修改内容、尚未完成或已复用的内容确认依据、验证证据、提交状态、未验证项和恢复条件；
- 尚未由上层创建提交时写明“由上层待生成并回填”，不得自行虚构 SHA；
- 出现新的产品、架构、公开接口或范围决策时，暂停处理，并交回统筹本次任务的 Skill。

### 独立调用

完成当前 Skill 后：

- 不自行构建下一个 Skill；
- 不创建下一个 Skill 的目录或占位文件；
- 不把提交、推送、发布或安装更新视为默认步骤；
- 根据目标仓库、远端和实际安装形态，只列出真实适用的动作：
  - Git 仓库可以列出 commit；
  - 已知远端与目标分支时可以列出 push；
  - 独立 Skill 已安装到 Claude Code 或 Codex 时，可以列出对应独立安装更新；
  - Skill 位于 Plugin 仓库且存在对应正式 Plugin 时，可以列出对应 Plugin 更新；
  - 普通项目或独立 Skill 不得虚构 Plugin、Marketplace 或客户端更新动作。
- 使用以下开头主动询问一次：

  ```text
  实现和验证已经完成。是否执行以下交付动作？
  ```

- 为每项动作写明真实目标，给出推荐答案，并明确用户可以全部授权或只授权其中部分动作。
- 不得在用户回答前执行任何交付动作；收到回答后只执行明确授权部分，未授权项保持未执行并记录在交付报告中。
- 提问后停止，等待用户授权；不得自行开始下一项任务。
