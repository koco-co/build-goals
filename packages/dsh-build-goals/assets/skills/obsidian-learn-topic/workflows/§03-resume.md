# 恢复学习主题

## 1. 定位三层路线

1. 通过 `obsidian bases` 找候选，再验证根过滤器和三层视图。
2. 读取 `01-*概述/§01-学习路线图.md`，以 `roadmap_status: 进行中` 定位活动路线，并核对版本基线和完整单元目录。
3. 缺少路线图、学习记录目录或三层 Base 视图的既有路线标记为旧合同路线；转入 `workflows/§06-maintain.md` 生成迁移预览，不直接写入或假装已经迁移。
4. 用户未给主题时，只在多个进行中路线之间询问一次选择；不从聊天记忆猜测。

## 2. 检查版本与当前记录

1. 新单元前按路线图检查官方资料、版本基线和上游状态。
2. 发现破坏性变化、弃用或依赖变化时展示影响，确认继续固定基线或迁移；迁移只通过路线图 compare-and-swap 更新 Commit 与课程合同，普通正文写入不能顺带改基线。安全风险或不可用步骤直接阻断。
3. 仓库路线先执行只读 `upstream-check`，不更新 checkout。
4. 查询 `学习中` 和 `待复习`；它们只返回 `learning-evidence`。
5. 当前学习记录有待回答题时先恢复该题，回答完成回写前不得选择新单元。

## 3. 选择下一单元

只有当前记录事务结束后，才按路线图的依赖、顺序和状态选择下一单元。正文尚未创建时进入 `workflows/§04-learn-unit.md`；正文存在但学习记录缺失时先报告合同漂移并进入维护流程，不在正文内补写问答流水账。
