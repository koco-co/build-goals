# §03 写入指令

## 写入顺序

1. 再次检查目标文件与预览时相比是否变化；若发生重叠变化，停止并刷新预览。
2. 按确认正文写入根 `AGENTS.md`。
3. 按确认范围写入必要的嵌套 `AGENTS.md`，只补充与根文件不同的内容。
4. 为每个目录建立同目录 `CLAUDE.md -> AGENTS.md` 相对符号链接。
5. 平台不支持符号链接且预览已说明回退时，写入内容精确为 `@AGENTS.md` 的普通文件。
6. 检查工作区差异，确认没有范围外文件变化。

已有 `AGENTS.md` 可以整体重构，不需要保留失效章节；但项目事实、仍有效的关键约定和用户修改必须按预览迁移。已有普通 `CLAUDE.md` 被替换为链接属于文件类型变化，必须在操作表中明确列出。

## 内容写法

- 开头直接说明项目用途、主要入口和关键职责，不写欢迎语或通用 Agent 宣言。
- 使用仓库真实路径和可复制命令；详细解释优先链接到已有文档。
- 关键约定说明适用范围或违反后的具体影响，避免“注意质量”一类口号。
- 验证流程按文件类型或行为分类，避免每次无差别运行所有昂贵检查。
- 平台差异只在真实存在时出现，公共规则使用中立措辞。

## 禁止扩张

不得为了让指令看起来完整而新增 README、项目文档、lint、CI、测试 harness、脚本或配置。发现必要但缺失的工程能力时，在交付中报告为后续建议。

不得自动 commit、push 或更新本地 Plugin。写入结束后继续验证，不在中途索取发布授权。
