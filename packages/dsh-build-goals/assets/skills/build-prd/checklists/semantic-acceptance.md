# 产品需求包语义验收清单

## 功能覆盖

- [ ] 每项需求、异常、边界、恢复、兼容、校验和禁止结果都有用户输入、产品事实、公开契约、外部证据或已确认决策依据。
- [ ] 功能域地图覆盖所有用户角色、入口、命令、页面、后台能力和跨域旅程。
- [ ] 小需求也有一个明确功能域；大需求的依赖顺序和跨域契约一致。
- [ ] 完整包无遗漏；阶段包范围闭合、延后范围和外部依赖契约明确。
- [ ] 每个 `F-NNN`、验收 ID 和行为样例 ID 唯一、稳定并互相追踪。

## 输入与行为

- [ ] 每项功能明确用户真正会提供的文字、字段、文件、命令、选择、状态或上下文。
- [ ] 输入表格只记录产品实际存在的必填性、范围、默认值、校验规则和示例。
- [ ] 信息不足时的追问、可推导内容和必须由用户决定的内容清楚。
- [ ] 每项功能至少有正常行为样例；信息不足、无效、不适用和边界样例仅在产品存在对应行为时添加。
- [ ] 样例不含秘密或个人敏感数据；脱敏不会改变要验证的行为。

## 输出与兼容

- [ ] 输出分别写清固定结构、语义要求和运行时可变内容。
- [ ] 完整示例与输入、交互、最终文案和验收标准一致。
- [ ] 命令、路径、格式、公开 API、文件和错误行为等用户依赖已记录。
- [ ] 需求确有禁止结果时，表述具体可检查，不使用“不要出错”一类空泛表达。
- [ ] 需求只约束外部可观察结果，没有强迫新项目复制旧内部实现。

## 交互与验收

- [ ] 已确认的入口、主流程、分支、取消、失败和恢复有明确后续动作。
- [ ] 所有用户可见文案都是最终文本，并与触发条件匹配。
- [ ] Given/When/Then 只描述用户状态、操作和外部可观察结果。
- [ ] 产品质量要求可重复测量，不依赖内部技术术语。

## 证据与边界

- [ ] 已实现现状、用户目标和外部实践没有混为一谈。
- [ ] 影响产品决策的调研来源可直接复核，没有为了凑数量加入无关资料。
- [ ] 没有工具调用、访谈逐字稿、模型推理、失败尝试或旧项目内部架构。
- [ ] 没有 TODO、TBD、假设、开放问题、待确认项、冲突或模板占位。
- [ ] 未实际运行的产品流程没有被描述为已通过。

## 文件与快照

- [ ] 正式产物只位于 `docs/产品需求/`，过程检查点只位于 `.build-goals/build-prd/`。
- [ ] 旧的 `docs/PRD需求文档.md` 已完成一次性迁移，不存在长期双写。
- [ ] 包内无符号链接、绝对路径、未声明文件或哈希漂移。
- [ ] 清单的包 ID、版本、状态、类型、功能域依赖、来源和文件哈希真实准确。
