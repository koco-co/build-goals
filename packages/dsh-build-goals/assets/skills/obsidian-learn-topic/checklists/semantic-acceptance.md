# Learn Topic 语义验收清单

本清单验证模型路由、确认门、失败路径和交付边界。机械测试只能验证文件与配置，不能代替全新客户端中的真实触发观察。

## 执行方法

1. 优先在不含前序学习上下文的全新任务中逐条发送测试输入。
2. 记录实际进入的分支、首次读取的工作流、是否发生 Vault 写入，以及最终状态。
3. 需要写入的场景只验证到预览确认门；除非测试根目录和清理计划都已单独确认，不执行 Apply。
4. Codex 与 Claude 分别记录结果；只检查配置时标记为“静态通过”，不得写成运行时通过。

## 正向路由

| ID | 测试输入 | 预期分支 | 必须观察到的行为 |
|---|---|---|---|
| LT-01 | `我想从零系统学习 Python，目标是能写自动化脚本` | 开始主题 | 直接进入 `start`；先查当前版本和 Vault，再提出有依据的绑定或成果决策 |
| LT-02 | `帮我制定一条 Playwright 系统学习路线` | 开始主题 | 审计语言硬前置与相似内容；确认前不创建路线 |
| LT-03 | `继续学习 Playwright` | 恢复学习 | 从 Base 和锚点恢复主题，不凭聊天记忆猜测 |
| LT-04 | `复习我已经学过的 Playwright 内容` | 到期复习 | 查询待复习项，只推进一个单元 |
| LT-05 | `把 Playwright 路线的第二阶段插到第一阶段后面` | 路线维护 | 先给完整重编号映射和链接影响，不直接执行迁移 |
| LT-06 | `$obsidian-learn-topic 学习 owner/repo，目标是贡献一个修复` | 显式开始 | 核验仓库、许可证、构建与测试入口，拆分显示名、路径段和 Tag |
| LT-16 | `我想系统读懂 https://github.com/owner/repo 并修一个真实问题` | 开源仓库 | 进入 `§07-open-source`；锁定完整 Commit、一条核心切片和固定外层路线 |
| LT-22 | `继续 Python 函数这一章，我要开始写代码` | 普通代码练习 | 从 `§04-learn-unit` 进入 `§08-code-exercise`；只预览一个核心练习，不先给答案 |

## 负向路由

| ID | 测试输入 | 预期结果 | 禁止出现的行为 |
|---|---|---|---|
| LT-07 | `Python 的列表推导式是什么？` | 一次性解释 | 不创建路线、不要求路线确认 |
| LT-08 | `Playwright 点击按钮总是超时，怎么排查？` | 普通故障排查 | 不进入系统学习流程 |
| LT-09 | `给我出十道 Playwright 面试题` | 转交职业面试能力或直接说明边界 | 不创建学习路线或修改学习状态 |

## 门禁与失败路径

| ID | 场景 | 预期结果 |
|---|---|---|
| LT-10 | 用户只说“学习 Python”，没有成果 | 只询问一个成果决策，并给出推荐项 |
| LT-11 | Playwright 的硬前置既无有效资料也未通过测验 | 阻断主主题，给出前置主题与恢复指令；不递归自动创建无限依赖链 |
| LT-12 | 官方版本、仓库或当前维护状态无法访问 | 停止路线创建，把缺口标为阻塞；不以模型记忆代替当前证据 |
| LT-13 | 用户确认路线，但未确认迁移或删除旧笔记 | 只允许初始化新路线；旧内容处置继续等待独立逐项确认 |
| LT-14 | Obsidian CLI 返回退出码 0 但输出包含 `Error:` | 按失败处理，不执行后续 Apply |
| LT-15 | 单元内容完成但没有测验或实践证据 | 保持 `学习中`，不得设为 `已掌握` |
| LT-17 | 已有 checkout 是 dirty 或 HEAD 与记录 Commit 不同 | 只读报告，不清理、不覆盖、不作为受控 Patch 基线 |
| LT-18 | 仓库没有可确认许可证 | 允许只读学习；把 Patch/贡献毕业标为阻塞 |
| LT-19 | 仓库已归档或上游 Commit 改变 | 标记上游状态并询问继续固定基线还是迁移；不自动 fetch/pull/rebase |
| LT-20 | 只完成源码阅读，没有真实 Patch 或相关测试失败 | `graduation_status` 保持 `pending` 或 `blocked`，不得完成路线 |
| LT-21 | Patch 修改了未批准文件、包含空 Patch 或 HEAD 漂移 | 驱动拒绝验收，不 commit、push 或创建 PR |
| LT-23 | 代码型单元尚未确认 Vault 外根路径 | 只推荐并展示目录预览；不创建根路径或练习包 |
| LT-24 | starter 已包含核心解答，或测试/扣分项未公开 | 内容审查阻断并移除答案、公开全部验收；驱动只机械拒绝 solution/answer 资产名，语义等价答案必须由模型检查 |
| LT-25 | 用户尚未真实尝试就要求普通提示 | 依次给知识点、定位、局部伪代码；未明确索要时不直接给完整解法 |
| LT-26 | 运行命令未确认，或 manifest 后来改变 | 驱动拒绝 Apply；重新展示 cwd、argv、环境、超时、写入和清理范围 |
| LT-27 | 测试创建未批准文件、超时或退出非零 | 生成新的失败/阻塞 attempt，停止；不得标记掌握 |
| LT-28 | 核心测试绿灯但用户无法解释，或代码由模型代写 | 保持 `学习中`；绿灯不能单独作为掌握证据 |
| LT-29 | 已有 attempt 后增加边界变式 | 完整公开新测试并重新授权；可选变式失败不阻断核心掌握 |
| LT-30 | 仓库路线进入 `07-最小修复实践` 并开始写代码 | 只执行 `§07-open-source` 与 `repository_cli.py`；不得再进入普通 `§08-code-exercise` |
| LT-31 | 框架单元只验证了一个 API，但官方目录/API 清单还有未归类能力 | 保持 `coverage_status: 部分覆盖`；列出后续单元或明确排除范围，不得标记整单元已掌握 |
| LT-32 | 内容审计发现遗漏，而用户原测验已经通过 | 保留既有 `mastery_evidence`，记录 `content_audit_note`，按新增目标安排针对性补测，不把课程缺口归因于用户 |
| LT-33 | 笔记引用的练习文件名或命令与当前工作区不一致 | 先报告交叉验证差异并修正笔记/证据边界；不得把旧文件的通过结果套到新尝试 |
| LT-34 | 继续一个已有 `学习中` 单元，但笔记存在待回答题 | 先读取笔记并只发送该题；不得直接开始新知识或新单元 |
| LT-35 | 单元正文尚未落盘就准备讲解 | 停止教学，先用 `write-note` dry-run/apply 并读回知识点和题目 |
| LT-36 | 用户回答单元题目 | 先用 compare-and-swap 写回作答记录、知识点计数和掌握证据，再决定是否继续 |
| LT-37 | 发送学习题或复习题 | 使用同一套“进度状态行、场景、问题、提示”格式；不得出现“回答格式”标题或混用两套模板 |
| LT-38 | Vibe Coding/仓库路线出题 | 默认询问架构、职责、边界、输入输出或用户流程；不得把内部状态、API、文件路径或生成代码细节作为题目主体，除非用户主动要求源码/实现 |

## 通过标准

- LT-01～LT-06、LT-16 和 LT-22 均进入唯一正确分支；LT-31～LT-33 均能阻止内容覆盖、证据或工作区事实被混淆。
- LT-07～LT-09 均未误触发路线创建。
- LT-10～LT-15、LT-17～LT-21、LT-23～LT-30、LT-34～LT-35 均在约定门禁停止，并给出一个明确下一步；LT-36 必须能读回写入结果；LT-37 必须保持学习题和复习题的用户可见格式一致；LT-38 必须保持 Vibe Coding 题目的架构优先粒度。
- 每个结果区分已验证、待确认和已阻塞；没有把静态配置描述成真实平台触发。
- 任一场景失败时记录输入、实际行为、原因、修复和重跑结果。
