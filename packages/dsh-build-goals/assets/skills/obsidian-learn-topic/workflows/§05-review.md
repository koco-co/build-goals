# 到期复习

复习也必须读写当前笔记的 `knowledge_points_total`、`knowledge_points_covered` 和 `knowledge_points_pending`；复习题的答案与证据不能只留在聊天中。

1. 通过 Base 查询 `待复习`，按 `next_review` 和依赖优先级选择一个单元，并读取当前笔记精确快照和知识点计数。
2. 先做无提示主动回忆，再做变式问题、常见误区或最小实践；不直接展示原答案。每一道题遵守 `SKILL.md` 的 `Question contract`，对用户只发送四部分：进度状态行、`场景`、`问题`、`提示`；验证目标和通过标准留在内部评定或笔记中。
3. 当前消息只发送一道短题，发送后立即停止本轮；不能重复长背景、并列多个追问或要求用户重抄代码。用户回答后用三句以内反馈：`结论`、`原因/遗漏`、`下一步`，再通过 `write-note` compare-and-swap 回写作答记录、复习属性和知识点计数；读回完成后才可发下一题。
4. 结合原笔记中的重点、踩坑和面试追问验证迁移能力，而非原句背诵。
5. 证据足够时更新：
   - `last_reviewed`
   - `next_review`
   - `review_count`
   - `mastery_score`
   - `mastery_evidence`
   - `assessment_type`
   - `assessment_at`
   - `learning_status`
6. 第 1 次通过后安排 `+7d`，第 2 次通过后安排 `+30d`，此后按表现调整；失败时记录薄弱点、缩短间隔并链接回对应学习笔记，必要时将状态改回 `学习中`。
7. 只有笔记仍为 `已发布` 且证据非空时保留 `已掌握`；读取精确旧快照后，全部属性通过 `write-note` compare-and-swap 更新并读回。
8. 只有路线内所有必修单元和最终综合实践均通过时，才把锚点 `roadmap_status` 改为 `已完成`；到期复习不会把已完成路线误改回进行中。
9. 每次只复习一个知识单元，然后给出下一次可直接发送的自然语言指令；显式 Skill 语法仅作为可选补充。
