# 架构方案验收清单

## 需求与事实

- [ ] 每项架构、工具、分支、兜底、兼容、校验、权限门禁和提示词都有用户需求、项目事实、平台契约、可复现缺陷或明确安全要求依据。
- [ ] 路线 1–3 的需求包已严格校验，包 ID、版本、类型、功能域、功能、验收和行为样例已提取。
- [ ] 项目路线来自用户自然语言；旧项目“不读取 / 指定范围 / 当前项目基线”边界已明确。
- [ ] 路线 2 的只读检查只返回行为、输入、输出、公开契约和证据，没有带入旧架构或代码转储。
- [ ] 迁移路线的当前架构和高优先级 Findings 有文件或命令证据。
- [ ] 已确认事实、外部参考和未知项彼此区分；推断没有进入实施依据。
- [ ] 用户现有修改和稳定接口的保护方式明确。

## 调研

- [ ] 实际影响架构决策的外部资料有一手来源。
- [ ] 版本与维护状态按当前日期核对。
- [ ] 比较了真实可行方案；只有一个可行方案时，排除依据明确。
- [ ] 推荐不是由热度、个人偏好或“最新”单独决定。
- [ ] 外部代码、文案和资产的许可证边界清楚。

## 目标架构

- [ ] 技术栈与约束匹配，工具职责不重复。
- [ ] 目录树、模块职责和依赖方向清楚。
- [ ] 项目实际存在的数据、API、事件、配置和错误契约明确。
- [ ] 项目存在对应数据、权限、秘密或隐私边界时有设计。
- [ ] 已确认质量目标所需的测试数据、测试层级、CI 或视觉验证有方案。
- [ ] 需求涉及部署、可观测性、恢复或迁移时，相应边界明确。
- [ ] 实际比较过的权衡与已证实风险明确。
- [ ] 每项需求或迁移目标能映射到架构组件。

## 确认门禁

- [ ] 方案只在对话中预览，确认前没有项目写入。
- [ ] 用户已明确确认推荐架构和排除项。
- [ ] 全局及功能域架构文档写入后无 TODO、TBD、待确认或模板占位。
