# 写入预览与确认门禁

使用 `templates/readme-preview.template.md` 输出一次可实施预览。

## Phase 1：项目理解摘要

先说明：

- 项目解决什么问题；
- 已实现哪些主要能力；
- 谁会使用以及最短成功路径；
- 哪些结论已验证，哪些仍未知。

摘要必须让用户能够纠正事实，而不是只看到视觉风格名称。

## Phase 2：README 内容预览

逐章列出准备写入的真实内容。常见章节包括简介、能力、工作流、安装、快速开始、使用、配置、验证、兼容性和许可证；没有信息价值的章节不创建。

同时说明：

- 现有内容中哪些保留、重组或删除；
- 每个表格、Mermaid、SVG、流程图或插图表达什么关系；
- Shields 的标签、数据来源和目标链接；
- 图片或 SVG 的存放路径与替代文本；
- 是否存在需要同步的伴随 README。

视觉核心样式以 `rules/github-style.md` 为准，预览不再重复确认。表格和视觉元素按内容价值选择，不为了凑齐类型制造图示。

## Phase 3：外部动作与验证预览

单独列出可能发生的外部动作：

- 生成图片；
- 请求远程 Shields 或文档链接；
- 把 README 内容发送到渲染 API；
- 调用项目已有但可能耗时的测试。

没有列出的外部动作不得在实施阶段临时增加。安装依赖、提交、推送和发布不包含在 README 写入确认中。

## Phase 4：请求确认

只提出一个确认问题：是否按该预览修改列出的 README 和资源。

用户要求调整时更新预览；用户只需要审查时在此停止。未获得明确确认时不得创建、修改、移动或删除任何目标文件。
