# 检查领域契约

## 范围

本 Skill 固定覆盖五个项目规范领域：

1. Agent Skill；
2. Plugin；
3. README；
4. AGENTS.md 与 CLAUDE.md；
5. 正式 PRD 需求包。

代码质量、安全、依赖、测试覆盖率、CI 和性能不在本 Skill 的检查范围。发现这些领域的线索时只说明本轮未检查，不扩张审计范围。

## 统一返回字段

每个领域的只读审查只返回：

- 问题：违反的现有契约或缺失的必要产物；
- 证据：文件、配置、命令结果或已确认项目事实；
- 修复方案：能够闭合问题的具体改动；
- 影响文件：预计新增、修改、移动或删除的准确路径；
- 验证方式：修复后应运行的静态检查与适用场景。

没有证据支持的问题不进入报告。每个问题只归属一个主领域；跨领域影响写进同一项的影响文件，不复制成多个问题。

## 领域路由

### Agent Skill

- 有独立或项目级 Skill 时，由 `build-skill` 检查结构、Frontmatter、调用策略、内容、引用、验证与平台适配。
- Plugin 内已包含的 Skills 由 Plugin 领域统一检查，本领域不重复检查。
- 没有 Skill 时，只在仓库证据表明同一 Agent 工作流已经重复出现并且具有稳定输入、步骤、输出和验收时，报告可抽取 Skill；没有重复证据则记为未发现问题。

### Plugin

- 存在 Plugin 时，由 `build-plugin` 检查 Manifest、组件发现、Skill 纳入、共享镜像、平台适配、版本与分发契约。
- 没有 Plugin 时，只在仓库已经存在跨项目安装、组件打包、多平台分发或版本发布需要时，报告需要建立 Plugin；普通项目没有 Plugin 不构成问题。

### README

- 由 `build-readme` 对照稳定项目事实检查 README 的存在必要性、功能、安装、运行、验证、限制和本地引用。
- README 缺失不自动构成问题；只有当前项目确实需要面向使用者的仓库入口时才报告。
- 修复前仍须展示具体 README 修改预览并取得内容确认。

### AGENTS.md 与 CLAUDE.md

- 由 `build-agents-md` 检查项目指令是否必要、是否与真实目录和命令一致，以及 CLAUDE.md 是否为有效的仓库内相对符号链接。
- 新项目基线阶段只记录现状；工具链和真实命令尚未稳定时，不因文件尚未创建而报告问题。
- 修复前仍须展示完整正文和全部文件操作并取得内容确认。

### 正式 PRD 需求包

- 由 `build-prd` 检查项目是否需要正式需求包，以及现有 `docs/产品需求/` 是否已确认、完整、可复制且与当前对外行为一致。
- 普通实现仓库没有正式 PRD 需求包不自动构成问题；当项目流程以需求快照为权威输入，或存在跨项目复制产品行为的明确需求时才适用。
- 修复涉及未决定的产品行为时，保留功能域与跨域确认；已有等价确认不重复询问。

## 阶段范围

- 基线检查点：检查当前路线成立所需的输入和已有产物；新项目不检查尚未到创建时点的 README 或项目指令。
- 就绪检查点：脚手架与真实命令稳定后检查项目指令和当下已生成的规范产物，问题修复前不得进入功能开发。
- 最终交付检查点：五个领域全部按最终项目事实检查，问题修复并复检前不得完成交付。
