# GitHub README 视觉规范

本文件是 `build-readme` 视觉系统的唯一规范源。

可机检的视觉规范（居中首屏、花体标题、一句话描述字形、英文 `<b>` 标签、斜体与粗体禁用、Shields 徽章下限、锚点、围栏语言、SVG 安全、HTML 配对）由 `scripts/validate_readme.py --strict` 强制，字形范式见 `examples/readme.example.md`；本文件只保留脚本无法判断的“何时、为什么”原则。

## 1. Shields 徽章

- 徽章至少 2 枚，通常控制在 3–7 枚，全部与仓库事实相关。
- 同一徽章行使用一致的风格、大小和颜色体系；标签含义、版本对象和目标链接必须准确，客户端版本、模型版本和项目版本不得混淆。
- 动态徽章只引用真实仓库、工作流或包；不存在 License 时不得显示 MIT、Apache 等许可证徽章。

## 2. 表格取舍

- 只有存在三项以上重复字段或明确映射时使用表格。
- 表头简短，单元格内容便于快速浏览；移动端难以阅读的宽表拆分为列表或多个表。
- `<details>` 只用于次要长内容、平台差异或故障排查，不隐藏首次成功所需步骤。

## 3. 图表与图片

- Mermaid 用于真实流程、依赖、状态或组件关系，不用于装饰；图中名称与代码、命令和文档保持一致，复杂图拆分、不堆叠全部文件。
- SVG 用于可维护的品牌图、架构图或轻量插图，存入仓库并使用相对路径；图片必须帮助理解产品、界面、输入输出或工作流，使用相对路径、具体替代文本和适合浅色/深色背景的对比度。
- 同一种关系只用 Mermaid、SVG 或静态图片中的一种形式表达，避免多份图示内容不一致。
- 优先复用仓库已有品牌资源；不使用随机图库、未经许可的 Logo、外部热链或含有不可核实产品 UI 的生成图（徽章除外）。

## 4. 可读性

- 首屏之后尽快给出项目作用、关键能力和首次成功路径。
- 装饰不能替代事实，图像不能成为唯一信息来源；保证命令可复制、链接可访问、图片有替代文本、章节有稳定导航。

## 5. 诚实声明

- 仓库没有许可证时明确写“尚未声明”，不得根据代码风格猜测许可证。
- 不虚构功能、版本、兼容性、性能、测试、许可证、贡献者、维护状态或外部认可；未验证项必须如实标注。
