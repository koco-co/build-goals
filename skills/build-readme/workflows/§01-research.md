# 项目事实探索

本阶段只读取和验证，不修改目标文件。

## Phase 1：确定边界

1. 确认项目根目录、目标 README 路径和当前 Git 分支。
2. 检查工作区状态，记录 README、文档和资源目录中的未提交修改。
3. 枚举现有 `README*` 文件；只有实际存在的伴随 README 才进入同步候选。
4. 读取适用的 `AGENTS.md`、项目规则和文档约定。

如果 README 已有并行修改，后续预览以当前工作区版本为基线，不覆盖、不还原、不擅自归因。

## Phase 2：建立功能地图

按项目实际技术栈检查：

- Manifest、包管理和锁文件；
- 应用、库、CLI、服务或插件入口；
- 公开 API、命令、参数和配置；
- 测试、Lint、构建、CI 和发布入口；
- 示例、演示、截图、图标、SVG 和已有品牌资源；
- 安装前提、平台兼容、许可证和贡献方式；
- 现有 README 中仍有效的内容、链接、徽章和限制说明。

使用代码搜索、帮助命令和无副作用检查补足证据。不要仅因 README 提到某条命令就执行安装、下载、发布、迁移或连接外部服务。

## Phase 3：整理证据

每个准备写入的主要事实标记为：

```text
已验证：由代码、配置、测试或实际命令直接证明
合理推断：多处证据一致，但没有完成真实运行
未知：仓库和安全的只读检查仍无法确定
```

至少形成：

- 项目一句话定位；
- 目标用户和主要使用场景；
- 功能列表和主要工作流；
- 安装、快速开始和常用命令；
- 配置、输入输出和已存在的失败行为；
- 测试、兼容性、限制和许可证状态；
- 值得用表格或图表表达的关系。

## Phase 4：完成条件

- 现有 README 与伴随文档已读取；
- 所有计划写入的命令能追溯到仓库入口；
- 没有把静态发现写成真实业务或生产验收；
- 没有仍可通过仓库查明的事实留给用户回答；
- 足以提交具体写入预览，且尚未改动文件。
