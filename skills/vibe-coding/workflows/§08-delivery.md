# 交付与停止

## Phase 1: 固化交付证据

使用 `templates/delivery-report.template.md` 创建或更新 `docs/交付验收报告.md`，至少包含：

- 基线与最终 HEAD；
- 架构、任务和 PRD 产物；
- 需求追踪矩阵；
- 任务、Agent、worktree 与 commit 清单；
- 实际运行的命令和结果；
- 正常测试数据；
- UI、交互、无障碍和视觉结果；
- 安全、环境变量和秘密检查；
- 已验证、未验证和阻塞项；
- 部署、发布和 push 状态。

所有结论必须有命令、文件、截图、日志或真实流程证据。

## Phase 2: 更新任务清单

将 `docs/实施任务清单.md` 中每个任务更新为：

- 完成、阻塞或取消；
- commit SHA；
- 测试证据；
- 集成状态；
- 偏离及批准依据。

不删除历史任务来制造 100% 完成率。

## Phase 3: 最终一致性检查

确认：

- 架构文档、代码和目录一致；
- PRD、任务、测试和提交闭环；
- README 和运行说明没有过时；
- Git 工作区干净；
- 临时 worktree 已在安全集成后清理；
- 没有未授权 push、发布或部署。

README 需要更新时，转交 `build-readme` 并遵循其预览确认门禁。会话过长或需要跨环境继续时，转交 `handoff`。

## Phase 4: 最终回复

按以下顺序报告：

1. 完成范围；
2. 最终架构和主要变化；
3. 文档与代码产物；
4. 功能与提交；
5. 测试和测试数据；
6. UI、交互与安全验证；
7. 已验证、未验证和阻塞；
8. 未执行的 push、发布或部署；
9. 可复现命令。

交付后停止，不自行开始新需求、下一个项目或额外平台适配。
