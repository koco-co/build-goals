# 项目特有信息准入

`AGENTS.md` 是执行入口，不是面向 Agent 的百科全书。候选内容只有同时通过以下问题才应进入正文：

1. 它能从当前仓库、已确认的外部依赖或用户决策中得到证据吗？
2. 它会改变 Agent 在这个项目中的定位、修改、验证或交付方式吗？
3. 删除它后，后续 Agent 是否更可能做出具体且可预见的错误？
4. 它是否应放在根作用域；若只影响一个子树，是否应放入嵌套 `AGENTS.md`？

无法通过的问题应删除、链接到已有项目文档，或留在 Skill 自身，而不是写成泛化口号。

## 优先写入

- 前十行内能建立心智模型的项目定位、技术栈和主要入口。
- 实际目录与职责边界，尤其是容易改错位置或重复实现的区域。
- 从仓库证据得到的构建、测试、格式化和聚焦验证命令。
- 违反后会造成兼容性、发布、数据、安全或架构问题的项目不变量。
- 不同变更类型对应的最小验证闭环，以及仓库已有的详细文档链接。
- 项目特有的生成物、源文件、平台差异和单一来源规则。

## 默认排除

- “先理解需求”“保持代码整洁”“不要泄露密钥”等通用 Agent 行为。
- 可从语言或框架常识直接推出、且仓库没有特殊差异的编码教程。
- README 已完整表达、又不会改变修改决策的产品宣传或背景历史。
- 未在仓库中出现的命令、目录、工具、性能指标或发布承诺。
- 为追求章节完整而加入的空标题、占位文本和重复表格。

## 自适应结构

根文件通常只需要“项目定位、工作地图、关键命令、项目不变量、变更与验证、交付边界”中的适用部分。应用、库、CLI 与 Monorepo 的重点不同，不强制固定九章。

120 行是复查提醒，不是硬门槛。超过时应检查是否可删减、下沉至嵌套文件或链接到既有文档；即使内容确有必要，也不得仅因行数阻断交付。

## 命令证据

命令按证据分三类：

- 已实际运行：记录命令、环境范围和结果。
- 来源已确认、运行未验证：命令来自 Manifest、CI、脚本或权威项目文档，但因成本、凭据或环境限制未执行。
- 未确认：不得写成推荐命令；继续研究或在预览中明确提出缺口。

安全且低成本的只读或本地校验应在写入后实际运行。安装依赖、访问生产、发布、迁移数据库或使用凭据的命令不得为了“验证文档”自动执行。

## 嵌套准入

只有子树满足至少一项时才建立嵌套文件：

- 使用不同技术栈或工具链；
- 有独立构建、测试或运行命令；
- 存在根规则无法准确表达的架构边界或硬性约定；
- 团队需要在该目录作用域覆盖根级规则。

仅因目录存在、代码量较大或想复制相同命令，不应创建嵌套文件。每个嵌套文件只写相对根规则的增量，不重复根正文。
