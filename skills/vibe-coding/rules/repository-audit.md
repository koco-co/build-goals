# 全仓审查规范

## 1. 审查以证据为中心

每条发现必须包含：

- ID；
- 领域；
- 文件、目录、命令或运行证据；
- 当前行为；
- 影响；
- 严重度；
- 推荐目标；
- 验证方式。

严重度：

- **Blocking**：数据、权限、秘密、构建、核心功能或不可逆迁移风险；
- **High**：显著影响正确性、维护性、扩展性或测试；
- **Medium**：增加成本或不一致，但有可控替代；
- **Low**：局部质量和体验改进。

个人风格偏好不是缺陷。

## 2. 目录与代码

检查：

- 根目录职责；
- 源码、测试、脚本、文档和资源分层；
- 模块边界与依赖方向；
- 重复、死代码、生成物和临时文件；
- 文件、函数、类、组件和变量命名；
- 注释、错误处理、日志和配置；
- 公共接口与内部实现；
- 数据模型、迁移和兼容层。

## 3. Prompt 与 Agent 资产

检查：

- Prompt、Skill、Agent、Hook、MCP 的职责是否混淆；
- 触发边界、输入输出和完成条件；
- 是否存在多段重复提示词代替脚本；
- 是否泄露秘密或发送过量上下文；
- Agent 文件命名和返回契约；
- 平台专属配置是否隔离；
- 同一规则是否有多个权威源。

## 4. AGENTS.md 与 CLAUDE.md

检查：

- 根规则是否简洁、可执行并与仓库事实一致；
- 子目录规则是否只覆盖局部差异；
- 构建、测试、格式和安全命令是否真实可运行；
- 是否说明禁止修改区域、生成文件和秘密；
- 是否重复 README 或复制大量通用知识；
- 是否存在平台未知字段、过时命令或互相冲突的指令。

需要同时支持 Claude Code 与 Codex 时，按 `build-agents-md` 采用 `AGENTS.md` 正文和同目录 `CLAUDE.md` 单一来源入口；不得复制两份正文，也不得为没有局部差异的目录创建多余指令。只有目标平台或文件系统约束不同，才按证据采用对应回退。

## 5. README 与文档

检查：

- 安装、运行、测试和目录说明是否可复现；
- 功能、版本、兼容性和许可证是否有证据；
- 架构图和示例是否与代码一致；
- 文档是否有唯一权威入口；
- 需求包、架构、任务和验收是否职责清楚；
- 过期、重复或冲突文档是否需要合并。

README 需要系统更新时转交 `build-readme`。

## 6. 忽略文件与生成物

检查：

- `.gitignore`；
- `.dockerignore`；
- npm/PyPI/crate 等发布忽略；
- IDE、缓存、构建、覆盖率、日志和临时文件；
- 测试产物与截图；
- 本地数据库和上传文件。

忽略规则不得掩盖应该提交的锁文件、迁移、fixture 或配置示例。

## 7. 密钥与环境变量

检查已跟踪文件中的：

- `.env`；
- token、API key、密码、私钥和证书；
- 云服务凭据；
- 真实用户数据；
- 硬编码环境地址；
- 默认管理员密码。

目标状态：

- 秘密由环境或秘密管理系统注入；
- 仓库只保留无秘密的 `.env.example`；
- 配置有类型、默认值、必填说明和启动校验；
- 测试使用隔离凭据和数据；
- 日志、错误和截图不泄露秘密。

发现真实秘密时不在报告中回显值，只报告位置、类型和轮换建议。

## 8. 工具链与质量

检查依赖管理、锁文件、运行时版本、格式、Lint、类型、pre-commit、测试、CI/CD、容器、部署、可观测性、性能、安全、无障碍和恢复。

迁移建议必须说明收益和成本，不进行无理由批量升级。
