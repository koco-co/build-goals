# PRD需求文档

- 文档状态：已确认
- 更新时间：2026-08-10

## 产品定位与范围

### 产品作用

帮助个人把零散事项快速整理为清晰、可执行的任务，并随时确认完成状态。

### 目标用户与角色

- 普通用户：创建、查看并完成自己的任务。
- 键盘用户：无需使用指针设备即可完成全部任务操作。

### 范围边界

- 包含任务创建、任务列表、完成反馈及输入错误恢复。
- 不包含团队协作、收费能力和项目排期。

### 产品成功标准

- 新用户能在一分钟内完成首次任务创建。
- 有效输入提交后，用户在一秒内看到成功结果或可执行的失败反馈。

## 产品现状与目标

### 已实现现状

当前产品已提供只读任务列表，但没有创建入口和完成反馈。

### 目标需求

补全任务创建、输入校验、完成状态和用户反馈体验，使用户能够独立完成从记录到确认完成的闭环。

## 功能地图与用户旅程

- `F-001` 创建任务：记录一项待办事项。
- `F-002` 完成任务：把未完成任务标记为已完成。

普通用户进入任务页，通过 `F-001` 创建任务，在列表顶部确认创建结果，完成事项后通过 `F-002` 更新状态并获得明确反馈。

## 全局交互与文案原则

- 主要操作使用动词开头的简短标签，例如“创建”和“标记为完成”。
- 错误反馈同时说明原因和下一步动作，并保留用户仍可修正的输入。
- 成功反馈说明已经发生的结果，不使用“操作成功”等泛化文案。

## 功能详细设计

### F-001 创建任务

#### 作用与目标

让用户快速记录一项需要完成的事项，并立即在任务列表中确认结果。

#### 适用角色、入口与前置条件

- 角色：普通用户、键盘用户。
- 入口：任务页顶部“新建任务”按钮。
- 前置条件：用户已进入任务页。

#### 用户预输入

| 字段或内容 | 提供者   | 必填 | 格式与范围  | 默认值 | 校验规则               | 正确示例 | 错误示例 |
| ---------- | -------- | ---- | ----------- | ------ | ---------------------- | -------- | -------- |
| 任务名称   | 普通用户 | 是   | 1–80 个字符 | 无     | 去除首尾空格后不能为空 | 预约牙医 | 空字符串 |

#### 交互流程

1. 用户点击“新建任务”。
2. 产品显示“任务名称”输入框、“创建”和“取消”按钮，并把焦点置于输入框。
3. 用户输入任务名称并点击“创建”。
4. 产品将新任务显示在列表顶部，关闭输入区域并公布创建结果。

#### 状态与提示文案

| 状态     | 触发条件               | 最终文案                 | 后续动作                         |
| -------- | ---------------------- | ------------------------ | -------------------------------- |
| 输入为空 | 用户提交空内容         | “请输入任务名称”         | 保留输入区域并聚焦任务名称输入框 |
| 输入过长 | 用户输入超过 80 个字符 | “任务名称最多 80 个字符” | 保留已输入内容供用户修改         |
| 创建成功 | 有效任务创建完成       | “任务已创建”             | 返回任务列表并聚焦新任务         |
| 用户取消 | 用户点击“取消”         | “已取消创建任务”         | 关闭输入区域并返回“新建任务”按钮 |

#### 期望输出

| 输出内容 | 呈现形式   | 触发条件 | 排序或状态                 | 用户后续动作       | 完整示例          |
| -------- | ---------- | -------- | -------------------------- | ------------------ | ----------------- |
| 新任务   | 任务列表项 | 创建成功 | 位于列表顶部、状态为未完成 | 标记完成或继续创建 | 预约牙医 · 未完成 |

#### 异常、边界与恢复

- 输入为空或过长时保留输入区域与已有内容，显示具体错误并聚焦输入框。
- 用户取消时不创建任务，焦点返回“新建任务”按钮。
- 列表原本为空时，首个任务创建成功后移除空状态并显示新任务。

#### 产品质量要求

- 用户提交后 1 秒内看到成功结果或可执行的失败反馈。
- 输入、创建和取消操作均可通过键盘完成，焦点移动与视觉顺序一致。
- 成功与错误反馈会通过辅助技术公布，但不会意外移动用户正在编辑的焦点。

#### 设计依据

- 采用单字段快速创建方式，减少首次记录任务的操作负担。
- 错误时保留输入并聚焦可修正位置，降低恢复成本。

#### 验收标准

- `F-001-AC-01` Given 用户位于任务页，When 输入“预约牙医”并点击“创建”，Then 列表顶部显示状态为“未完成”的“预约牙医”，并提示“任务已创建”。
- `F-001-AC-02` Given 任务名称为空，When 用户点击“创建”，Then 显示“请输入任务名称”、保留输入区域并聚焦任务名称输入框。
- `F-001-AC-03` Given 用户正在输入任务，When 点击“取消”，Then 不创建任务、提示“已取消创建任务”并把焦点返回“新建任务”按钮。

### F-002 完成任务

#### 作用与目标

让用户明确记录事项已经完成，并能立即识别任务状态变化。

#### 适用角色、入口与前置条件

- 角色：普通用户、键盘用户。
- 入口：每个未完成任务旁的“标记为完成”控件。
- 前置条件：任务列表中至少存在一项未完成任务。

#### 用户预输入

| 字段或内容 | 提供者   | 必填 | 格式与范围                 | 默认值 | 校验规则                     | 正确示例          | 错误示例         |
| ---------- | -------- | ---- | -------------------------- | ------ | ---------------------------- | ----------------- | ---------------- |
| 目标任务   | 普通用户 | 是   | 当前列表中的一项未完成任务 | 无     | 已完成任务不显示重复完成入口 | 预约牙医 · 未完成 | 选择不存在的任务 |

#### 交互流程

1. 用户在未完成任务旁点击“标记为完成”。
2. 产品立即将该任务显示为已完成状态。
3. 产品提示具体任务已经完成，并保留用户在任务列表中的位置。

#### 状态与提示文案

| 状态         | 触发条件         | 最终文案               | 后续动作                 |
| ------------ | ---------------- | ---------------------- | ------------------------ |
| 完成成功     | 状态更新完成     | “已完成：预约牙医”     | 查看下一项任务           |
| 更新失败     | 产品未能更新状态 | “未能完成任务，请重试” | 保留未完成状态并重新尝试 |
| 列表全部完成 | 最后一项任务完成 | “今天的任务已全部完成” | 创建新任务或离开任务页   |

#### 期望输出

| 输出内容   | 呈现形式             | 触发条件 | 排序或状态                   | 用户后续动作   | 完整示例          |
| ---------- | -------------------- | -------- | ---------------------------- | -------------- | ----------------- |
| 已完成任务 | 任务列表项和状态提示 | 完成成功 | 状态为已完成，保留原列表位置 | 查看下一项任务 | 预约牙医 · 已完成 |

#### 异常、边界与恢复

- 更新失败时任务保持未完成，不显示相互矛盾的完成样式。
- 失败反馈提供“重试”动作，并保留用户当前列表位置。
- 最后一项任务完成后显示全部完成状态，但仍保留任务列表供用户核对。

#### 产品质量要求

- 用户操作后 1 秒内看到状态变化或失败反馈。
- 状态不能只依赖颜色表达，同时提供文字和辅助技术可识别的状态。

#### 设计依据

- 使用任务名称组成具体成功文案，让用户能确认哪一项发生了变化。
- 更新失败时保留原状态，避免视觉结果与实际结果冲突。

#### 验收标准

- `F-002-AC-01` Given “预约牙医”处于未完成状态，When 用户点击“标记为完成”，Then 该任务显示“已完成”并提示“已完成：预约牙医”。
- `F-002-AC-02` Given 产品未能更新任务状态，When 用户点击“标记为完成”，Then 任务保持未完成并显示“未能完成任务，请重试”。
- `F-002-AC-03` Given 列表只剩一项未完成任务，When 用户将其标记为完成，Then 保留任务列表并显示“今天的任务已全部完成”。

## 跨功能产品要求

- 所有交互均可通过键盘完成，焦点顺序与视觉顺序一致。
- 状态变化同时通过文字、视觉样式和辅助技术可识别的信息表达。
- 错误反馈必须说明原因或结果、用户下一步动作，并保留仍可恢复的输入或页面位置。
- 所有主要操作在触发后 1 秒内显示最终结果或明确的处理中状态。
