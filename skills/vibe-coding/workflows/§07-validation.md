# 全链路验证与验收

## Phase 1: 需求和任务追踪

确认：

- 每个 `F-NNN` 和 `F-NNN-AC-NN` 都映射到至少一个任务和测试；
- 每个迁移高优先级发现都有处理结果；
- 每个任务都有 commit SHA、验证命令和最终状态；
- 没有用“基本完成”“大致支持”代替明确结果。

## Phase 2: 机械质量门禁

按项目实际运行：

1. 格式检查；
2. Lint；
3. 静态类型检查；
4. 依赖与锁文件一致性；
5. 构建或打包；
6. 单元测试；
7. 集成测试；
8. 端到端测试；
9. 数据库迁移与回滚测试；
10. 安全、秘密和依赖检查。

禁止通过删除测试、弱化断言、排除文件或关闭规则让流水线变绿。

## Phase 3: 正常测试数据

测试环境必须包含能覆盖主流程的正常业务数据，而不只有空状态、mock 文案或异常样本。

验证：

- 数据可重复创建；
- 角色、权限和关联关系正确；
- 数据不会进入生产；
- 测试结束后有清理或隔离策略；
- UI、API 和存储观察到的是同一份业务状态；
- 截图和报告不泄露秘密或个人数据。

## Phase 4: UI 与交互条件分支

仅当项目存在前端、GUI、TUI 或可视组件时执行：

- 首屏与关键路径视觉检查；
- 响应式尺寸；
- 组件状态、键盘、焦点和无障碍；
- 加载、空、错误、权限和恢复状态；
- 浏览器控制台、网络错误和资源加载；
- 截图或视觉回归；
- 真实组件交互和端到端路径。

界面不得包含脏数据、调试文本、TODO、PRD 原文、用户口述文案、模板占位符或彼此不一致的同义字段。

## Phase 5: 归一化与仓库治理

核对：

- 输入、输出、错误、状态、日期、枚举和命名归一化；
- 设计 token、组件、表单、反馈和交互一致；
- API/CLI/UI 契约与文档一致；
- 目录、文件、函数、类和注释符合项目选定规范；
- 注释优先使用用户交流语言，技术标识保留英文；
- AGENTS.md、CLAUDE.md、README、忽略文件和环境变量说明与事实一致；
- 不存在已跟踪秘密、临时构建物、调试日志和未知生成文件。

## Phase 6: 独立复核与最终校验

调用独立 Reviewer，并按项目类型调用 UI 和 Security Reviewer。所有 Blocking Finding 修复后重跑。

写入 `docs/交付验收报告.md` 后执行：

```bash
python3 <vibe-coding>/scripts/validate_delivery.py \
  <project-root> \
  --mode <greenfield|migration> \
  --phase delivery \
  --require-clean \
  --strict
```

无法完成真实客户端、外部服务或生产等价验证时，标记为未验证，并说明缺少的证据和影响。
