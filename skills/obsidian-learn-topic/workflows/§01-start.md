# 启动新主题

## 1. 建立事实基线

1. 运行 `obsidian help`；失败时停止 Vault 操作。
2. 读取 `rules/research-policy.md`、`rules/vault-audit-policy.md` 和 `rules/curriculum-design.md`。
3. 解析主题、最终成果和显式限制。零基础是教学基线，不询问“会多少”来改变讲解起点。
4. 缺少可验证成果时只询问一个成果决策，并给出推荐答案。
5. GitHub URL、`owner/repo` 或读懂/修改/贡献目标立即转入 `workflows/§07-open-source.md`。

## 2. 消歧与前置审计

1. 通过当前官方资料查明仍受维护的版本、语言绑定和实现分支。
2. 通过 Obsidian CLI 检索已有前置、相似内容、目录语义和命名风格。
3. 提出一个版本/绑定推荐并等待确认，不让零基础用户盲选。
4. 把前置分为硬前置、可随课补齐和拓展知识。硬前置缺失、失效或未通过时，停止主主题并给出前置主题、最低成果和恢复指令。
5. 相似内容只形成复用、更新、迁移、合并、归档或回收站删除候选；路线确认不授权处置。

## 3. 逆向设计完整路线

1. 先定义路线最终成果，再为每个单元定义一个可观察成果和一种验收方式。
2. 从 `templates/curriculum-plan.template.json` 建立全部单元，而不是只规划目录。
3. 为每个单元选择教程、原理解释、操作指南或参考资料之一。
4. 建立依赖图和“知识点 → 唯一所属单元”映射；拒绝循环、重复归属和前置倒置。
5. 正式目录按 `01、02、03……` 连续编号，末尾增加连续编号的 `NN-学习记录`，固定保留 `99-assets`。
6. `01-<主题>概述` 规划：
   - `§01-学习路线图.md`
   - `§02-前置准备.md`
   - `§03-<主题>概述.md`
   - 其他确有独立成果的扫盲正文
7. 未学习的单元只记录在路线图，不创建空白正文或空白学习记录。

## 4. 预览并暂停

预览包含：版本基线、推荐路径、完整目录树、完整单元目录、依赖图、知识点唯一归属、正文类型、单项成果、验收方式、Base 视图、前置结果、相似内容候选、一手来源和写入范围。

等待路线确认。迁移、合并、归档或删除仍需独立确认。
