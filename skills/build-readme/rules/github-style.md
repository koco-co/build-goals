# GitHub README 视觉规范

本文件是 `build-readme` 视觉系统的唯一规范源。

## 1. 首屏

使用 GitHub 可渲染的居中 HTML 容器：

```html
<div align="center">
  # 𝓟𝓻𝓸𝓳𝓮𝓬𝓽 𝓝𝓪𝓶𝓮

  <p align="center">中文一句话描述 · 𝑬𝒏𝒈𝒍𝒊𝒔𝒉 𝑻𝒂𝒈𝒍𝒊𝒏𝒆</p>

  <!-- Shields -->
</div>
```

- 拉丁字母项目名使用 Mathematical Bold Script 花体；非拉丁项目名保留原文，不用不可搜索的图片替代语义标题。
- 一句话描述使用 `<p align="center">...</p>`；中文保持普通字体，短英文使用 Mathematical Bold Italic 字形，不得使用 `***`、Markdown 粗体或 HTML 斜体标签模拟。
- 默认提供项目主要语言和简洁英文的一句话描述；已有语言政策优先。
- 不使用内联 CSS、JavaScript、远程字体或 GitHub 会过滤的样式属性。

## 2. Shields

- 至少 2 枚，通常控制在 3–7 枚；全部必须与仓库事实相关。
- 优先展示目标平台、语言或运行时、CI、包版本、许可证和真实兼容状态。
- 同一徽章行使用一致的 Shields 风格、大小和颜色体系。
- 标签含义、版本对象和目标链接必须准确；客户端版本、模型版本和项目版本不得混淆。
- 动态徽章只引用真实仓库、工作流或包；不存在 License 时不得显示 MIT、Apache 等许可证徽章。
- 写入时验证 URL；网络不可用时明确标记未验证。

## 3. 章节标题与锚点

章节使用居中的 HTML heading，英文部分统一使用 Mathematical Bold Italic：

```html
<a id="overview"></a>
<h2 align="center">𝑶𝒗𝒆𝒓𝒗𝒊𝒆𝒘 · 简介</h2>
```

- 同一 README 的章节语言、字号层级和分隔方式保持一致。
- 每个 HTML 章节标题前显式提供稳定、唯一的锚点。
- 不把普通章节标题全部转换成 SVG；保留可搜索、可链接和可被辅助技术识别的文字。

## 4. 正文

- 中文段落和列表说明使用普通字体。
- 英文正文使用 `<b>English</b>`；短标题和一句话描述可使用既定的 Mathematical Bold Italic 字形。
- 表格中的中文说明使用普通字体，英文说明使用 `<b>English</b>`；路径、命令、API、版本号和状态值保持原样。
- 不使用 Markdown 下划线斜体；禁止使用 HTML `<i>` 或 `<em>` 斜体标签。
- `<b>` 仅用于英文标签，不用于中文正文；正文不得使用 Markdown `**`、`__` 或 HTML `<strong>` 粗体。
- 代码块、行内代码、命令、路径、URL、徽章、图表语法和机器可读内容不转换字形、不斜体。
- 围栏代码块必须声明语言；无语法高亮需求时使用 `text`。
- HTML 标签必须正确配对，不保留字面量 `span` 等格式转换残留。
- 不把长篇正文转换为 Mathematical Unicode；装饰字形只用于短标题和短描述。

## 5. 表格与折叠内容

- 只有存在三项以上重复字段或明确映射时使用表格。
- 表头简短，单元格内容可以扫描；移动端难以阅读的宽表拆分为列表或多个表。
- `<details>` 只用于次要长内容、平台差异或故障排查，不隐藏首次成功所需步骤。

## 6. Mermaid、SVG 与流程图

- Mermaid 用于真实流程、依赖、状态或组件关系，不用于装饰。
- 图中名称与代码、命令和文档保持一致；复杂图拆分，不堆叠全部文件。
- SVG 用于可维护的品牌图、架构图或轻量插图；存入仓库并使用相对路径。
- SVG 必须是有效 XML，不嵌入脚本、事件处理器、`foreignObject`、远程资源、跟踪像素或敏感数据。
- 同一关系只选择 Mermaid、SVG 或静态图片中的一种权威表达，避免重复图示漂移。

## 7. 图片与生成插图

- 图片必须帮助用户理解产品、界面、输入输出或工作流。
- 优先复用仓库已有品牌资源；生成图片仅在用户预览确认且客户端支持时使用。
- 默认存入现有资源目录；没有约定时使用 `assets/readme/`。
- 使用相对路径、具体替代文本和适合浅色/深色背景的对比度。
- 不使用随机图库、未经许可的 Logo、外部热链或含有不可核实产品 UI 的生成图；Shields 与 GitHub Actions 徽章除外。

## 8. 可读性

- 首屏之后尽快给出项目作用、关键能力和首次成功路径。
- 装饰不能替代事实，图像不能成为唯一信息来源。
- 保持命令可复制、链接可访问、图片有替代文本、章节有稳定导航。
