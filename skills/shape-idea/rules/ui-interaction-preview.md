# UI 交互预览规则

当本次决策会改变前端、GUI、TUI 或 CLI 的可见界面与操作流程时，使用本规则。没有可见界面变化时不生成占位预览。

## 1. 覆盖范围

- 覆盖本次变更所影响的完整用户流程，包括理解变化所必需的前后状态。
- 枚举该流程中的所有可达界面状态，不扩展到无关页面，也不为假想风险制造状态。
- 按实际行为覆盖初始、加载、内容、空数据、成功、失败、禁用、权限受限和结束状态；不适用的状态不补齐。
- 当前决策改变任一状态、操作或转换时，重新展示受影响的完整流程；没有变化的已确认内容不机械重复。

## 2. 可见界面状态

使用 `templates/ui-interaction-preview.template.md`，按 `## 状态 N：<名称>` 逐一展示。每个状态必须包含：

1. 使用代码块绘制完整的文本界面；
2. 进入条件；
3. 当前可用的用户操作；
4. 每项操作的结果与下一状态。

文本界面必须能够看出信息层级、关键文案、控件、禁用或选中状态及主要内容变化。字符边框、间距和尺寸只表达大概效果。

## 3. 不可见状态流

在可见状态之后使用代码块展示不可见状态流，覆盖实际存在的触发、判断分支、业务或技术状态、数据更新、失败恢复、循环和结束条件。

- `shape-idea` 只展示用户能够理解的业务流程和产品规则，不提前决定技术栈、数据库或模块结构。

## 4. 交互契约

最终确认后，下列内容构成交互契约：

- 必须存在的界面状态与后台状态；
- 每个状态的信息、控件和关键文案；
- 用户操作、判断条件和状态转换结果；
- 数据何时更新、失败后如何恢复、流程如何结束。

真实实现可以优化视觉风格，但不能擅自删除或改变已确认状态与交互。字符边框、具体间距、尺寸和视觉风格不是像素级验收标准。

## 5. 确认与保存

- 对话中的探索版本不写入项目；最终确认时展示一份合并后的完整预览。
- `shape-idea` 的结果只保留在对话和最终共同理解中。
