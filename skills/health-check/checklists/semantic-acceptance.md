# Health Check 语义验收

## 范围与证据

- [ ] 只检查五个确认领域，没有扩张到代码质量、安全、依赖、测试覆盖率、CI 或性能。
- [ ] 每个适用性判断和问题都有仓库事实、平台契约、可复现缺陷或用户明确要求依据。
- [ ] Skill 审查覆盖最小充分原则；无法说明用途或重复规范源的内容会被具体报告。
- [ ] 新项目基线没有把尚未到创建时点的产物报成问题。
- [ ] Plugin 内 Skills 没有与独立 Agent Skill 领域重复报告。
- [ ] 没有 Skill 或 Plugin 时，只依据真实的重复工作或分发需要提出抽取建议。

## 交互与修复

- [ ] 检查阶段只读，首次输出是一次性报告。
- [ ] 每个问题都包含证据、修复方案、影响文件和验证方式。
- [ ] 没有发现问题时没有增加确认交互。
- [ ] 用户确认后直接把问题交给对应领域修复，没有要求用户选择内部 Skill。
- [ ] 尚未展示的 README、项目指令、产品行为或公开契约仍经过所属领域的内容确认。

## 验证与交付

- [ ] 每个已确认修复都运行了承诺的领域校验。
- [ ] 修复后重新运行健康检查，并保留未确认问题。
- [ ] 静态检查、真实运行和未验证结论准确区分。
- [ ] 对话中没有创建持久化健康报告。
- [ ] 未经授权没有 commit、push、发布、部署或更新本地 Plugin。
