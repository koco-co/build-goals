# Plugin 语义与场景验收

## 目标

- [ ] Plugin 解决用户真实的安装、组织或分发问题。
- [ ] 组件范围没有因为“以后可能需要”而膨胀。
- [ ] 目标、非目标和完成条件相互一致。

## 可执行性

- [ ] 另一个 Agent 能按照工作流完成新建、升级或迁移。
- [ ] 用户确认前保持只读。
- [ ] Skill 子任务能正确转交 `build-skill`。
- [ ] 平台不支持嵌套调用时有清晰交接路径。
- [ ] 失败和回滚行为可以预期。

## 平台体验

- [ ] Claude Code 中的名称、命名空间和调用方式清楚。
- [ ] Codex 中的安装源、Skill 名称和调用方式清楚。
- [ ] 用户能判断何时需要重载、重启或更新。
- [ ] 平台差异没有要求用户理解内部重复实现。

## 安全

- [ ] 权限与数据流可理解。
- [ ] MCP、Hooks、脚本和网络访问没有隐藏副作用。
- [ ] 软链接没有越界或引入主机敏感文件。
- [ ] 发布状态没有夸大。

## 交付

- [ ] 用户能复现全部验证命令。
- [ ] 已验证、未验证和阻塞项分列。
- [ ] 版本、提交、推送、Marketplace 与 Release 状态准确。
