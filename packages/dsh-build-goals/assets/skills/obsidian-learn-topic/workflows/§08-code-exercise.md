# 执行普通代码练习

本流程只服务非仓库代码型单元，遵守 `rules/code-exercise-policy.md`。

## 1. 设计与路径确认

1. 只设计一个必做核心练习，最多两个可选挑战；公开 starter、测试、argv、必要测试点、通过标准、评分和三级提示。
2. 模型推荐外部位置，但用户必须提供并最终确认一个已存在的 Vault 外绝对根路径。未确认时只交付预览，不创建根路径。
3. 独立脚本使用 `NN-名称.扩展名`；多文件项目只编号练习目录，内部保留生态文件名。

## 2. 初始化与授权执行

1. 从 `templates/code-exercise-manifest.template.json` 生成计划，先运行 `exercise_cli.py scaffold` dry-run，再 Apply。
2. 用户先完成真实尝试；首次尝试前不提供核心解答。
3. 运行前展示 cwd、argv、环境、超时、写入与清理范围，通过 `authorize` 固化确认。manifest 或命令变化后重新确认。
4. 使用 `run` dry-run 与 Apply；不使用隐藏测试，不降级绕过隔离。

## 3. 证据与掌握

1. 失败提示按知识点、位置/边界、局部伪代码三级递进。
2. 每次运行追加 `attempt-NN.json`；学习记录只保存 `exercise_id`、`attempt_id`、摘要、关键失败、得分和用户解释，不保存绝对路径或完整日志。
3. 测试通过后仍要求独立应用和边界解释；模型代写结果不能单独证明掌握。
4. 证据写回学习记录并读回后，返回 `workflows/§04-learn-unit.md` 的迁移验证与分类毕业；未完成回流前停止在当前单元。
