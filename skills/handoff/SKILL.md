# Outcome

将当前对话上下文整理为精简的交接文档，帮助新 agent 在下一次会话中继续工作。

## Routing

- 用户明确调用 `handoff` 时进入本工作流。
- 用户传入的参数描述下一次会话的用途，并用于定制 交接文档。
- 普通总结、文档编写或实现请求不得自动触发本 Skill。

## Steps

1. 总结当前会话上下文，使新 agent 能够接续工作。
2. 将交接文档保存到用户操作系统的临时目录，不得保存到当前工作区。
3. 在文档中加入名为 `suggested skills` 的章节，推荐下一位 agent 应调用的 Skills。
4. 如果用户传入参数，将其视为下一次会话的用途，并据此调整文档重点。
5. 文档成功写入后，为下一个 Agent 生成一段可直接复制的接续提示词；提示词必须引用交接文档的真实文件路径，并要求遵循文档中的目标、约束、已确认决策和后续步骤。
6. 如果 `suggested skills` 中存在下一位 Agent 接续任务时应显式调用的 Skill，将其真实名称以 `$skill-name` 形式写入提示词；没有适用 Skill 时不添加 Skill 调用。

## Delivery

- 交付一个位于操作系统临时目录的交接文档。
- 文档必须包含 `suggested skills` 章节。
- 文档内容应足够让新 agent 在下一次会话中恢复上下文并继续工作。
- 最终回复必须同时给出交接文档的真实文件路径，以及标题为 `给下一个 Agent 的提示词` 的独立代码块，确保用户可以直接复制。
- 没有需要显式调用的 Skill 时，使用以下句式，并将占位内容替换为真实文件路径：

  ```text
  请读取 `<真实文件路径>` 并继续完成其中记录的任务；严格遵循文档中的目标、约束、已确认决策和后续步骤。
  ```

- 存在需要显式调用的 Skill 时，使用以下句式，并将占位内容替换为真实 Skill 名称与文件路径：

  ```text
  请使用 `$skill-name`，读取 `<真实文件路径>` 并继续完成其中记录的任务；严格遵循文档中的目标、约束、已确认决策和后续步骤。
  ```

## Guardrails

- 不得将交接文档写入当前工作区。
- 不得忽略用户传入的下一次会话用途参数。
- 不得在文件写入成功前声称已经生成交接文档，也不得在最终提示词中保留占位路径或不存在的 Skill 名称。
