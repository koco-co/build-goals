# 语义与场景验收清单

只检查无法由脚本稳定判断的质量。

## 需求理解

- [ ] Skill 解决的是用户真实问题，而不是关键词表面匹配。
- [ ] 目标、非目标和完成标准彼此一致。
- [ ] 已知事实、合理推断和未知项被清楚区分。
- [ ] 没有重复询问用户已经回答或环境可以查明的问题。

## 可执行性

- [ ] 步骤能指导另一个 Agent 完成真实任务，而不是抽象口号。
- [ ] 分支条件足够明确，不需要依赖隐含上下文猜测。
- [ ] 每个输出都说明格式、位置和质量要求。
- [ ] 失败时能指出下一步，不会继续生成错误结论。
- [ ] 按需读取关系使初始上下文精简，同时不会遗漏关键规则。

## 表达质量

- [ ] 中文措辞自然、简洁、明确，没有生硬黑话。
- [ ] 规则没有相互矛盾、重复或循环引用。
- [ ] 强制禁止只用于安全、权限和明确边界。
- [ ] 示例展示的是可复用的最佳实践，而非低信息量样例。
- [ ] 模板提供必要结构，但没有把示例内容硬编码为固定答案。

## 安全与权限

- [ ] Guardrails 对应真实数据、权限、接口或外部副作用风险。
- [ ] 设计确认与执行、提交、推送、发布授权被明确区分。
- [ ] 示例、日志和报告不包含凭据、隐私数据或机器私有信息。
- [ ] 覆盖、删除、迁移和破坏兼容性前存在明确确认点。

## 交付可信度

- [ ] “已验证”均能追溯到命令、文件、测试或实际业务结果。
- [ ] 当前环境无法运行的内容被标记为“未验证”。
- [ ] 外部条件不足的内容被标记为“阻塞”。
- [ ] 用户能够根据报告复现检查并定位全部变更。
- [ ] 当前 Skill 完成后流程停止，没有擅自开始下一项任务。
