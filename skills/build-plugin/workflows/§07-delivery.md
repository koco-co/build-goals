# Plugin 交付

使用 `templates/plugin-delivery-report.template.md`。

交付内容必须让用户能够回答：

- 最终交付了什么；
- 哪些内容没有做；
- 分发包在 Claude Code、Codex、ZCode 与 Pi 中如何发现、安装和调用；
- 哪些文件是规范源，哪些是平台适配；
- 哪些文件是共享镜像、规范源在哪里，以及保留了哪些必要链接；
- Plugin 中的 Skills 是否通过 `build-skill` 规范；
- 实际运行了哪些命令；
- 哪些结论来自真实客户端，哪些只是静态检查；
- 当前版本是否已提交、推送、发布或仅在本地；
- 存在哪些未验证项或阻塞项。

## 按调用模式交付

先判断本次是独立调用，还是由 `health-check` 等其他流程统筹并调用。两种模式都必须完成交付报告，不得因任务由其他流程统筹而省略 Plugin 与 Skill 的验证结果。

### 受控调用（由上层 Skill 统筹）

不重复询问 commit、push、Marketplace、Release、发布、部署或本地 Plugin 更新，也不自行执行。向统筹本次任务的 Skill 返回：

- 修改内容与确认依据；
- 静态校验、安装、真实客户端与 Skill 子任务的验证证据；
- 提交、版本、Marketplace 与 Release 当前状态；
- 未验证项；
- 恢复条件，以及是否允许继续依赖任务。

尚未由上层创建提交时明确写“由上层待生成并回填”。发现新的产品、架构、公开接口、权限或范围决策时，暂停处理，并交回统筹本次任务的 Skill。

### 独立调用

实现和验证完成后，根据目标仓库、远端、Marketplace 与已安装客户端，只列出真实适用的动作，并使用以下开头主动询问一次：

```text
实现和验证已经完成。是否执行以下交付动作？
```

候选动作包括：

1. Commit 当前任务变更；
2. Push 到明确的远端与分支；
3. 发布或更新明确存在的 Marketplace；
4. 更新并核验 Claude Code Plugin；
5. 更新并核验 Codex Plugin；
6. 更新并核验 ZCode Plugin，仅当本地安装了 ZCode 客户端时适用；
7. 更新并核验 Pi Package，仅当目标包含 Pi 且本地安装了 Pi 时适用；
8. 创建 Release，仅当目标仓库确实使用 Release 且前置条件已满足。

为每项动作写明真实目标、当前版本或拟发布版本，并给出推荐答案。明确用户可以全部授权或只授权其中部分动作。目标 Plugin 只支持一个平台时，不得列出另一平台更新；不存在远端、Marketplace、安装或 Release 流程时，不得虚构对应动作。

不得在用户回答前执行任何交付动作。收到回答后只执行明确授权部分，按依赖顺序完成并逐项核验；未授权项保持未执行并记录在交付报告中。

提问后停止。不要自动开始另一个 Plugin、发布到 Marketplace、创建 Release 或适配其他 Coding Agent。
