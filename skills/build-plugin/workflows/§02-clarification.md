# 关键决策澄清

## 提问条件

只有同时满足以下条件才提问：

1. 无法从需求、仓库、环境或平台文档中确定；
2. 用户此前没有回答；
3. 不同答案会改变结构、权限、安装、发布或验收结果。

没有真实未决事项时，写明“无待确认决策”，直接进入设计。

## 提问方式

每轮只询问一个主要问题，并包含：

```markdown
### 问题：<需要决定的事项>

**推荐：** <推荐选择>

**原因：**
<为什么更适合当前目标>

**其他选择的影响：**

- <选择 A>：
- <选择 B>：
```

## 常见决策

按需确认：

- 目标平台是 Claude Code、Codex 还是双平台；
- Plugin 是 Skills-only、MCP-only、混合型，还是包含 Hooks、Agents 或 UI；
- 新建、升级、迁移或包装已有组件；
- 用户级、项目级、Marketplace 或公开发布；
- 认证、网络、数据和权限边界；
- 版本兼容与破坏性迁移策略；
- 是否需要真实客户端测试；
- 哪些 Skill 已存在，哪些需要交给 `build-skill`；
- 哪些文件直接共用，哪些需要普通镜像，哪些必须平台独立。

完成条件：实现范围、平台差异、权限和验收标准都能被唯一解释。
