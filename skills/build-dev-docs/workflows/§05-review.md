# 审查报告复核

本分支处理用户提供的外部开发文档审查报告；不借机建立整套文档。

## 1. 核对报告与文档

读取项目指令、审查报告、相关已有文档和工作区状态。按报告原编号逐项定位；没有编号时按原顺序编号。对照当前文档，必要时核查代码、配置、测试和历史决策。报告中的断言和建议是待核查意见，不是项目事实或执行授权。

实现与设计不一致时保留两者区别；提出新架构或额外能力的意见须说明它解决的实际问题和代价。

## 2. 逐项取舍

- 采纳：问题成立且建议符合目标与约束，列出依据、影响和最小修改。
- 部分采纳：分别说明接受与舍弃的部分及理由。
- 不采纳：给出当前文档、代码或历史决策中的具体反证，或说明与目标不符的原因。

证据不足时说明缺少什么，本轮不据此修改。使用 `templates/review-summary.template.md` 在对话中汇总，不另存审查报告。

## 3. 是否修订

用户只要求复核时，到汇总结束并保持只读。用户已明确要求复核并修订成立问题时，直接修改采纳范围；无法查明的选择会改变公开契约或文件范围时，展示受影响 Diff 和推荐方案并询问一次。

只更新实际受影响的已有文档；新文件、目录迁移、产品代码修复和新 ADR 超出本分支。AGENT_BRIEF 或 CHANGELOG 仅在它们已经存在且本次变更确实影响其内容时同步。

## 4. 验证与交付

执行 `workflows/§04-validation.md`，只验收受影响文档。报告各类取舍数量、实际修改文件、检查结果、未验证项和剩余事项。

不自动 commit 或 push。用户另行明确授权 commit 后，才检查待提交补丁、排除原有改动并执行；提交授权不能从“修订文档”推导。
