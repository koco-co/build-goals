# 启动新主题

## 1. 探测与恢复事实

1. 运行 `obsidian help`；失败时停止所有 Vault 操作。
2. 读取 `rules/vault-audit-policy.md` 和 `rules/research-policy.md`。
3. 解析用户主题、想达到的成果和显式限制。教学基线固定为零基础，不询问“你会多少”来改变讲解起点。
4. 若用户没有给出可验证成果，一次只询问成果决策并给出推荐项。
5. 输入是 GitHub URL、`owner/repo`，或成果包含读懂/修改/贡献开源项目时，立即转入 `workflows/§07-open-source.md`，不把仓库当普通技术主题自由规划目录。

## 2. 消歧技术选择

1. 通过当前官方文档、官方仓库和发布记录查明仍受维护的版本、语言绑定和分支。
2. 通过 Obsidian CLI 检索知识库已有语言、工具链和前置知识。
3. 根据成果、维护状态和知识库证据提出一个推荐组合，说明替代项与代价。
4. 等待用户确认；不要要求零基础用户从无解释的版本列表中盲选。

## 3. 审计前置与相似内容

1. 按 `rules/vault-audit-policy.md` 搜索标题、别名、标签、正文、链接和现有目录。
2. 将依赖分为硬前置、可随课补齐和拓展知识。
3. 对既有前置笔记检查 `status`、`verified_at`、`version_scope`、来源和实际内容；时间只触发复核。
4. 对相似内容生成动作候选：Wikilink 复用、原地更新、迁移、合并、归档或删除。
5. 硬前置缺失或失效时，停止主主题并给出：
   - 缺口与最低掌握标准。
   - 推荐的前置主题。
   - 可直接发送的自然语言指令：`学习 <前置主题>，目标是 <最低成果>`；也可补充 Codex `$obsidian-learn-topic ...` 或 Claude `/obsidian-learn-topic ...` 的显式写法。
   - 完成后直接说明“继续学习 <原主题>”；模型据此恢复原主题，也允许用户显式调用。

## 4. 调研路线

1. 完成路线级广度调研；缺少关键一手资料时停止。
2. 规划 `01-<主题>概述`、连续编号的正式阶段、深入/拓展阶段和复习/面试阶段。
3. 把主题拆为显示名、无 `/` 等路径分隔符的目录段和 Obsidian-safe Tag 段；`owner/repo`、`C++`、`C#` 等不得原样复用到三种位置。
4. `01-<主题>概述` 至少规划：
   - `§01-前置准备.md`：硬/软前置、环境、配置、最低测验。
   - `§02-<主题>概述.md`：5W1H、类比边界、竞品对比、视觉、第一批来源。
   - 其他确有价值的扫盲笔记。
5. 正式阶段只规划目录和学习成果；具体章节笔记在学习该单元时创建。
6. 固定预留 `99-assets`，后续 Canvas、图片或附件只写入该处；其他所有子目录也必须使用 `01-`～`99-`。
7. 路径不套默认值。先检查现有分类；找不到合适位置时，依据现有 emoji、语言和层级风格提出新根目录。

## 5. 预览并暂停

预览必须包含：

- 主题、成果、教学基线、版本范围和语言绑定。
- 推荐存放路径及选择理由。
- 完整目录树和每个阶段的验收成果。
- 显示名、路径段和 Tag 段的规范化结果。
- Base 的视图和关键 Properties。
- 硬前置结果、相似内容清单及建议动作。
- 核心一手来源、核验日期和仍未解决的证据缺口。
- 创建、导航更新和测试范围。

等待用户确认路线。迁移、合并或删除候选仍需另一次逐项确认。
