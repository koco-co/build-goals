# 安全与权限规则

## 最小权限

Plugin 只声明完成目标所需的工具、网络、文件和服务权限。不要用宽泛权限掩盖不清楚的工作流。

## 用户确认

以下事项需要明确授权：

- 写入或删除用户文件；
- 覆盖稳定接口；
- 提交、推送、发布或创建 Release；
- 安装依赖或修改全局环境；
- 启用网络、MCP、Hooks、遥测或持久化；
- 读取凭据、密钥或隐私数据；
- 提高权限或绕过沙箱。

## 数据流

每个 MCP、Hook 或外部服务都说明：

```text
读取什么
发送到哪里
为什么需要
保存多久
如何撤销
失败时如何处理
```

## 软链接

拒绝：

- 绝对软链接；
- 越过 Plugin 或 Marketplace 边界的链接；
- 指向用户主目录、系统目录、凭据或临时敏感文件的链接；
- 失效链接和循环链接。

## 发布

在真实发布前确认版本、变更说明、许可证、依赖、隐私说明和回滚方式。构建完成不等于允许发布。

实现和验证完成后，将 commit、push、Marketplace、客户端 Plugin 更新和 Release 合并为一次发布确认，只列出真实适用的动作并给出推荐答案。用户可以全部授权或只授权其中部分动作；在用户回答前不得执行，回答后也只能执行明确授权部分。
