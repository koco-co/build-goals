# 设计落实检查清单

本清单用于比较“已确认设计”和“最终实现”，不替代静态校验。

## 目标与范围

- [ ] 每个已确认目标都有对应实现或明确证据。
- [ ] 每个明确非目标都没有被意外纳入。
- [ ] 变更没有越过用户确认的路径和行为范围。
- [ ] 提交、推送、发布和破坏性操作均有独立授权。

## 路由与流程

- [ ] Outcome 能用一句话说明最终结果。
- [ ] 每个独立输入都能路由到唯一分支。
- [ ] 相邻但不属于本 Skill 的任务有明确退出方式。
- [ ] 每个阶段都有完成条件。
- [ ] 失败、无法继续和用户取消都有可预期结果。
- [ ] 用户确认前保持只读。

## 架构

- [ ] 每个目录和文件都有单一、必要职责。
- [ ] 没有空目录、空文件或未来占位内容。
- [ ] `SKILL.md` 保持主流程清晰，细节按需读取。
- [ ] 模板、示例、规则、工作流和 References 没有重复职责。
- [ ] 可确定性执行的内容已交给 CLI、脚本或测试。
- [ ] 每次事件必须自动发生的内容已放入 Hooks 或 CI。
- [ ] 项目级 Skill 复用了项目已有能力，没有复制业务实现。

## 平台适配

- [ ] 核心工作流只有一个规范源。
- [ ] 已按字段决策矩阵逐项判断 Frontmatter，没有机械保留或补齐可选字段。
- [ ] 平台专属字段没有污染其他平台配置。
- [ ] 调用权限由平台配置控制；允许模型调用时，`description` 或 `when_to_use` 已写清触发条件和排除条件。
- [ ] `compatibility` 只描述硬性环境要求；没有要求时已省略。
- [ ] 安装路径、权限和依赖符合目标平台当前契约。
- [ ] 无法等价适配的能力已明确降级。

## 验证设计

- [ ] 静态检查、内容审查、文案审查、内容回归和真实场景验证彼此分离。
- [ ] 重要变更已安排独立 Reviewer；不支持独立 Agent 时有明确降级说明。
- [ ] 正向、负向和失败路径都有测试。
- [ ] 验证命令可复现，失败返回非零退出码。
- [ ] 未验证内容和无法完成的内容不会被描述为已通过。
