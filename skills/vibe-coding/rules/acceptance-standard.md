# 最终验收标准

以下标准按项目适用性执行。任何“不适用”都需要项目事实支持。

## 1. 需求完整性

- 需求包纳入范围内的所有功能、验收 ID 和行为样例已实现并有测试证据；
- 所有高优先级迁移发现有处理结果；
- 没有遗漏角色、入口、状态、异常和恢复路径；
- 架构、任务、代码、测试和文档相互一致；
- 未确认的新功能没有混入交付。

## 2. 正常测试数据

- 平台中存在可复现的正常业务数据；
- 主流程能够从输入走到持久化和最终输出；
- 角色、权限、关联、日期和状态符合业务；
- 数据不来自生产，不泄露真实个人信息；
- 测试数据有创建、重置和清理方式；
- 交付截图、日志和报告使用安全数据。

## 3. 界面与交互

有 UI 时：

- 关键路径在目标视口真实可用；
- 加载、空、错误、成功、权限和恢复状态完整；
- 组件、间距、颜色、字体、状态和反馈一致；
- 键盘、焦点、语义、对比度和响应式满足项目要求；
- 控制台无未解释错误；
- 页面无脏数据、调试数据、占位符、TODO、PRD 原文、用户口述文案和开发备注；
- 文案是最终产品文案，不暴露内部字段或实现细节。

## 4. 归一化

以下内容只有一个权威契约：

- 输入字段和校验；
- 输出结构和错误格式；
- 时间、金额、枚举、ID 和分页；
- API、事件和 CLI 命名；
- 设计 token 与组件；
- 配置和环境变量；
- 日志和错误码；
- 同义状态和业务术语。

## 5. 工程质量

- 安装、启动、构建和测试可重复；
- 格式、Lint、类型、单元、集成和 E2E 全部通过；
- 依赖与锁文件一致；
- 关键路径有错误处理、日志和恢复；
- 没有死代码、未知生成物、调试输出和无理由忽略；
- 每个功能单元有独立 commit 和回滚边界；
- Git 工作区最终干净。

## 6. 安全与配置

- 无已跟踪秘密、私钥、真实 token 或生产数据；
- 环境变量已提取、分类和说明；
- 启动时校验必填配置；
- 权限最小化，认证和授权路径有测试；
- 日志、错误、截图和测试报告不泄露敏感信息；
- 依赖和供应链检查无未解释 Blocking/High 风险。

## 7. 仓库治理

- 目录职责清晰；
- 文件、函数、类、组件和变量遵循选定生态规范；
- 注释优先使用用户交流语言，技术名词保持准确；
- AGENTS.md/CLAUDE.md 与真实命令、边界和平台一致；
- README、架构、任务、运行和测试说明没有过时；
- 忽略文件既不提交垃圾，也不隐藏应版本控制的产物。

## 8. 证据

每项完成结论至少由以下一种支持：

- 命令及退出码；
- 测试报告；
- 文件或提交；
- 截图或视觉差异；
- 浏览器/组件交互记录；
- API、数据库或日志证据；
- 可重复的人工验收步骤。

文件存在本身不等于功能通过。
