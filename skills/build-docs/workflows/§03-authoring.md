# 分批编写

## 预览与写入

1. 按已确认顺序，每批只读取文档职责表中对应的模板；先核对目标文件最新内容，保留未提交修改。
2. 从零建立使用已确认设计；已有项目提取使用调研证据；持续更新只改本次受影响内容。沿用项目文档语言和排版，模板用于补齐职责，不原样复制占位符。
3. 展示本批完整内容或 Diff，以及同步的 AGENT_BRIEF、CHANGELOG 和入口变化。内容较多时拆成更小批次，不以标题列表代替内容预览。
4. 用户确认后写入本批文件。出现新的范围或架构决策时先解决该决策，再更新预览。
5. 检查本批引用与事实一致性后继续下一批。用户暂停时保留已确认成果，简短列出剩余批次；不把整套文档标为完成。

## 文档间的一致性

- 依据已确认路径映射建立交叉引用，从引用所在文档的目录计算相对路径和章节链接。AGENT_BRIEF 索引按职责分组，分组名不改变已有文档的实际位置。尚未写入的文档在索引标为“待建立”，用普通文字记录拟定路径，不创建失效链接；落盘后再换成链接。
- 分清设计、实现和验证状态。提取模式可标注“现状提取”，新方案标注“待确认”；待确认部分不写成已接受约束。
- 更新关键决策时保留原 ADR，新增记录说明替代关系，架构链接当前生效记录。没有历史依据的日期、备选和理由保持未知，不能用本次推测补写过去。
- 每批同步 AGENT_BRIEF 的状态、下一步及受影响索引；CHANGELOG 只追加本次实际文档变更或有依据的产品变更。无实质变化时不为调用次数增加日志。
- ROADMAP 的完成标记引用 Definition of Done 的实际证据；仅提取到代码时记录实现存在与缺少的验收证据，不自动勾选完成。

## AGENTS.md 入口

只增加或更新一行简短描述，实际路径使用相对于 AGENTS.md 的相对路径：

```markdown
项目状态与开发文档入口：@docs/spec/AGENT_BRIEF.md
```

已有入口指向其他位置时按实际映射更新，重复执行不追加相同入口，不整体重写 AGENTS.md。先写入对应 Brief，再写入入口；不要为这个入口创建或修改 CLAUDE.md。

这行是项目文档引用，不宣称所有客户端都会自动展开 `@` 文件内容。
