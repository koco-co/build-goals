# 路由与决策卡样例

## 宽泛语言目标

用户说“系统学习 Rust”时，先核验当前受维护通道、用户期望成果与 Vault 前置，再用一张综合决策卡推荐版本、路径和完整路线；不让零基础用户先解释 edition 差异。

## 多语言绑定框架

用户说“系统学习 WebDriver”时，调研仍受维护的语言绑定与目标生态。语言选择会改变前置和练习时，它才成为一个真实决策。

## 知识点

用户说“系统掌握幂等性”时走普通主题分支，采用真实副作用场景与 `concept-explanation`，而不是先创建十篇术语定义。

## 开源仓库

用户提供 `northstar-labs/river-cache`（虚构评测仓库）并要求读懂后修改时，走仓库分支：固定 Commit、只选一条核心切片、使用用户确认的外部 checkout，毕业要求真实 Patch 与相关测试。

## 负向边界

“这段代码为什么报错？”是普通故障排查；“解释一下所有权”是一次性问答。除非用户明确要长期系统学习，否则不创建路线。
