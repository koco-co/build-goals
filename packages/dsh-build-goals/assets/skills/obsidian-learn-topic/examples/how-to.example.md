# 操作指南样例：定位引入回归的提交

> [!example] 使用场景
> 当前分支测试失败，已知两周前的发布标签通过，需要找到第一个失败提交。

## 操作前检查

先确认工作树状态、一个确定通过的提交、一个确定失败的提交，以及能够稳定返回成功或失败退出码的测试 argv。测试不稳定时停止，因为二分结论不可信。

## 操作步骤

完整列出开始二分、标记好坏、自动运行测试、处理无法测试提交和退出二分的命令。每一步解释仓库状态会怎样变化，以及如何恢复。

## 成功验证

结果必须包含候选提交、该提交前后的测试对比和恢复后的原分支状态。只看到命令退出 0 不够，还要核验定位到的差异确实解释失败。

## 不适用场景

多个提交共同触发、依赖环境随时间变化或测试本身随机失败时，普通二分可能给出假因果。
