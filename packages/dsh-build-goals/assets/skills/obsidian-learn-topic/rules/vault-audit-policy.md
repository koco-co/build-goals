# Vault 前置与相似内容审计

## 审计范围

| 区域 | 允许的默认检查 | 默认处置 |
|---|---|---|
| 普通知识目录 | 标题、正文、Properties、链接、目录 | 可提出复用或维护方案 |
| `Clippings`、外部资料 | 作为来源候选读取 | 不自动迁移或改写 |
| 归档 | 标题、Properties、链接 | 读正文前说明理由 |
| `sensitivity: 敏感` | 不读正文 | 用户点名后再读取 |
| `.agents`、`.claude`、`.obsidian`、附件、`koco-co` | 排除 | 不作为知识内容候选 |

## Obsidian CLI 审计顺序

1. `obsidian folders` 和 `obsidian files`：理解当前分类与命名风格。
2. `obsidian search` / `search:context`：检索主题名、别名、术语、语言绑定和前置知识。
3. `obsidian properties` / `property:read`：检查状态、版本、时效和敏感级别。
4. `obsidian outline`、`links`、`backlinks`：判断内容覆盖和关系影响。
5. `obsidian bases` / `base:query`：检查既有路线和学习状态。
6. 必要时 `obsidian read`：完整比较普通候选正文。

命令显示 `Error:`、结构化错误或缺失结果时，即使进程退出码为 0 也视为失败。

## 前置分级

### 硬前置

缺失时无法理解核心机制、无法运行最小实践或会造成明显安全风险。缺失、失效或测验未通过时阻断主主题。

### 可随课补齐

可以在概述或相关正式单元中同步学习，不阻断启动。

### 拓展知识

只影响深度、效率或特定分支，作为链接或深入方向提供。

文档存在只证明知识库有材料。掌握要求当前有效材料，加上短测或最小实践证据。

## 相似内容分类

- **Wikilink 复用**：既有内容准确、当前且归属合理；路线只建立索引。
- **原地更新**：归属合理但内容缺失或过时；保留路径和入链。
- **迁移**：内容有效但目录语义明显错误；列出旧/新路径和链接影响。
- **合并**：多个文件实质重复且各有独有信息；先生成保留矩阵。
- **归档**：有历史价值但不适用于当前实践。
- **回收站删除**：重复、错误且无保留价值；必须逐项确认。

路线确认不等于处置确认。任何迁移、合并、归档或删除都生成独立动作清单并等待逐项确认。

## 路径选择

不设置固定根路径。依次判断：

1. 是否已有同主题或上位主题目录。
2. 文件夹是否表达长期领域归属，而非临时产物类型。
3. 当前目录语言、emoji、大小写和层级风格。
4. 是否能避免超过必要深度和重复导航。
5. 是否能从最近的 MOC 或 Base 获得入链。

找不到合适位置时，按最相近顶级目录的风格提出新根目录，仍需用户确认。
