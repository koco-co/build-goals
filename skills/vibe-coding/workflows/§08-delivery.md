# 交付与停止

## Phase 1：固化交付证据

使用 `templates/delivery-report.template.md` 创建或更新 `docs/交付验收/交付验收报告.md`，并用 `templates/domain-delivery.template.md` 为每个功能域写 `docs/交付验收/功能域/<功能域>.md`；按模板记录基线、追踪、任务、Agent/worktree、实际验证、配套 Skill、治理状态、未验证/阻塞项及外部动作状态。

需要判断交付报告粒度时读取 `examples/delivery-report.example.md`；示例不替代当前项目的实际证据。

所有结论必须有命令、文件、截图、日志或真实流程证据。

## Phase 2：更新任务清单

将 `docs/实施任务/功能域/<功能域>.md` 中每个任务更新为：

- 完成、阻塞或取消；
- commit SHA；
- 测试证据；
- 集成状态；
- 偏离及批准依据。

不删除历史任务来制造 100% 完成率。

同步更新 `docs/实施任务/实施任务清单.md` 的功能域状态、集成顺序和跨域验收结果，但不在全局文件复制每个任务正文。

## Phase 3：最终一致性检查

确认：

- 架构文档、代码和目录一致；
- 需求包、任务、测试和提交闭环；
- README 和运行说明没有过时；
- Git 工作区干净；
- 临时 worktree 已在安全集成后清理；
- 已完成任务没有残留已注册 worktree；保留项均有脏文件、独有提交、阻塞或既有所有权证据；
- 没有未授权 push、发布或部署。

完成上述一致性核对后执行 `health-check` 最终交付检查点。没有发现问题时不与用户交互；发现问题时暂停当前阶段，一次性报告，用户确认后直接组织修复、验证并复检。README 需要更新时仍展示具体修改预览，项目指令需要更新时仍展示完整正文与文件操作。复检通过前不得进入最终回复。会话过长或需要跨环境继续时，转交 `handoff`。

## Phase 4：合并受保护主分支

全部任务与最终质量门禁通过后，如果当前集成分支不是受保护主分支：

1. 报告集成分支相对主分支的完整提交、diff、测试结果和工作区状态；
2. 请求用户一次明确的本地合并授权；
3. 获准后在主工作树安全合并并重跑最终质量门禁；
4. 合并验证通过且集成 worktree 干净、无独有补丁时，移除本地集成 worktree 和分支；
5. 未获授权或合并失败时保留集成分支并准确报告，不 push、不强制解决冲突。

## Phase 5：最终回复

按模板顺序报告完成范围、验证状态、外部动作和可复现命令。

子 Skill 不单独询问交付动作。总控在实现和验证都结束后，只把当前任务仍适用且尚未授权的 commit、push、发布、部署或本地 Plugin 更新放入一次确认；用户可以只授权其中部分，回答前不得执行。

交付后停止，不自行开始新需求、下一个项目或额外平台适配。
