# 只读检查

## Phase 1：保护现场

记录目标项目、当前分支与 HEAD、工作区改动、已有 worktrees 和适用项目指令。全部既有改动属于用户；检查阶段只读，不执行清理、格式化、安装、迁移或 Git 写操作。

由上层总控调用时，读取检查点、项目阶段、允许范围、禁止修改项和恢复条件。独立调用时以当前项目最终事实为范围；阶段无法从仓库判断且会改变适用性时才询问用户。

## Phase 2：绘制项目形态

识别：

- 是否存在独立或项目级 Agent Skill；
- 是否存在 Plugin 及其包含的 Skills；
- README 及伴随文档；
- 根目录和局部 AGENTS.md / CLAUDE.md；
- 正式 PRD 需求包及其状态；
- 能证明重复工作或分发需要的仓库事实。

先按 `rules/domain-contract.md` 判断领域是否适用，再调用领域审查。缺少某种产物本身不是问题。

## Phase 3：受控领域审查

向每个适用领域 Skill 传递最小上下文：目标项目、检查点、只读要求、已有产物、相关证据、禁止范围和统一返回字段。

Plugin 领域检查其包含的 Skills；Agent Skill 领域排除这些路径。领域 Skill 必须执行自身现有校验和内容检查中可只读完成的部分，并区分实际命令结果、静态证据与推断。

## Phase 4：去重与一次性报告

合并领域结果，按同一根因和同一组修复文件去重。使用报告模板输出：

- `## 检查范围`；
- 无问题时输出 `## 未发现问题`；
- 有问题时输出 `## 发现的问题`，逐项包含证据、修复方案、影响文件和验证方式；
- 有问题时在末尾请求一次修复确认。

检查报告只留在对话中，不创建文件。上层总控需要持久化时，只把 `health-check` 的检查点、结论和修复状态写入其既有文档。
