# §02 完整替换预览

## 目标

让用户在任何写入发生前，看到最终文件内容和所有破坏性差异，而不是只确认一个抽象提纲。

## 必须展示

1. 项目理解：一句话定位、工作区边界、关键技术栈与本次问题。
2. 文件操作表：每个 `AGENTS.md` 和 `CLAUDE.md` 的新增、整体替换、删除、保留或链接动作。
3. 每个 `AGENTS.md` 的完整拟写正文；已有文件整体重构时标明“完整替换预览”。
4. 每个嵌套文件的必要性，以及为什么根文件不足。
5. 旧内容处置表：保留、泛化、下沉、移除及理由，特别列出 Claude 专有规则。
6. 命令证据：计划实际运行与“来源已确认、运行未验证”的命令。
7. 验收方式、剩余风险和明确排除项。

使用 `templates/replacement-preview.template.md` 组织输出，但删除不适用的章节，不能用占位符代替真实内容。

## 确认门

预览结尾只询问一个决策：是否按以上完整内容和文件操作写入。不得在用户确认预览前写入，包括“先创建空文件”“先修复链接”或“顺手更新文档”。

若用户修改某一部分，更新受影响的完整正文和操作表后再确认。确认只覆盖展示过的内容，不授权提交、推送、发布或本地 Plugin 更新。

## 冲突处理

若目标文件存在未提交修改：

- 将差异纳入事实表和完整预览；
- 能明确融合时展示融合后的完整正文；
- 无法判断所有权或会覆盖未知意图时，说明冲突并等待用户决策。

“允许整体重构”不等于可以覆盖预览之外的并发工作。
