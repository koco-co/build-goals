# 配套 Skill 生命周期

`vibe-coding` 负责判断何时需要配套 Skill、保护总流程边界并接收结果，不复制其他 Skill 的具体实现。每项能力都必须记录触发证据、调用阶段、是否阻断、恢复条件和交付记录。

## 生命周期矩阵

| Skill | 触发证据 | 调用阶段 | 是否阻断 | 恢复条件 | 交付记录 |
| --- | --- | --- | --- | --- | --- |
| `shape-idea` | 目标、范围或关键取舍尚不能形成可确认定义 | 进入项目调研前 | 阻断架构设计 | 用户确认完整定义 | 已确认目标及仍明确排除的范围 |
| `build-prd` | 需求包缺失、未确认、校验失败、哈希漂移或无法覆盖输入输出行为 | 基线与路线选择 | 阻断路线 1–3 | 完整或正式阶段需求包已确认并通过严格校验 | 包 ID、版本、类型、路径、状态与校验结果 |
| `build-agents-md` | 项目指令缺失、链接异常、与真实命令或目录冲突，或新增子项目需要局部规则 | 脚手架或基础工程能力验证后、功能开发前；交付前复查 | 阻断功能开发；已证实的最终漂移阻断交付 | 完整内容和文件操作已确认，写入、项目命令与严格符号链接校验通过，明确治理 SHA 已进入功能开发基线 | 状态、触发证据、确认依据、校验结果、冻结的治理 SHA 与最终漂移结果 |
| `build-skill` | 已确认架构包含新建或升级 Agent Skill | 架构与任务规划；按依赖实施 | 阻断依赖该 Skill 的任务 | Skill 内容与平台行为完成确认、实现和适用验证 | 任务、版本、验证、提交与未验证行为 |
| `build-plugin` | 已确认架构包含 Plugin 新建、升级、迁移或分发变化 | 架构与任务规划；按依赖实施 | 阻断依赖该 Plugin 的任务 | Plugin 结构、Manifest、平台适配和安装验证完成 | 任务、版本、双平台验证、提交与未验证行为 |
| `build-readme` | README 缺失，或安装、运行、功能与最终事实不一致 | 最终架构、命令和功能稳定后 | 错误的关键用户路径阻断交付；纯润色不阻断 | 修改预览已确认，README 写入并完成适用校验 | 修改范围、确认依据、渲染或静态验证与未验证内容 |
| `handoff` | 会话、客户端或执行环境必须切换，当前上下文不足以安全继续 | 任意阶段 | 暂停当前会话 | 下一个 Agent 已获得权威文件、当前状态、下一动作和可直接复制的接续提示 | 交接文档、接续提示和恢复起点 |

没有触发证据时记录“不适用”或“有效沿用”，不为了展示编排而调用 Skill、生成文件或制造提交。

## 调用方式

不要假设配套 Skill 一定能被当前 Agent 自动调用。先依据当前平台的实际调用能力判断：

- 平台明确支持并允许当前 Agent 受控调用时，才进入下述“受控调用”；
- 当前 Skill 配置或平台限制阻止受控调用时，直接进入“人工交接”，生成用户可复制的真实调用提示并暂停依赖任务；
- 受控调用由当前环境执行，不在交接提示中拼接平台命令；人工交接统一写“请调用 `<skill-name>`”，并使用真实 Skill 名称。

## 受控调用

平台支持受控调用时，向子 Skill 提供最小上下文包：

- 上层总控与任务 ID；
- 目标仓库、当前 HEAD、工作区和文件所有权；
- 已确认需求、架构、任务范围和禁止修改项；
- 本次触发证据、完成条件与恢复条件；
- 已确认的内容和仍需确认的内容；
- 本地提交是否由上层统一管理；
- 子 Skill 必须返回的结果字段。

子 Skill 返回后，总控记录：修改内容、确认依据、验证证据、提交 SHA、未验证项和恢复条件。出现新的产品、架构、公开接口或范围决策时，回到对应全局门禁，不允许子 Skill 自行扩展。

## 按需产物确认

架构确认和任务确认不会授权写入用户尚未看过的产物。配套 Skill 仍按自身规则保留具体预览或内容确认：

- `build-agents-md` 展示完整正文和全部文件操作；
- `build-readme` 展示具体修改预览；
- `build-skill`、`build-plugin` 和 `build-prd` 提交尚未决定的行为或内容；`build-prd` 的逐功能域确认不由总控第二次实施确认替代。

同一内容已经在上层被完整、等价确认时，可以把该确认作为依据，不机械重复提问。子 Skill 不单独询问 commit、push、发布、部署或本地 Plugin 更新；本地原子提交由总控按已确认任务管理，外部动作在最终交付时统一请求授权。

## 人工交接

平台不能受控调用配套 Skill 时，不在 `vibe-coding` 中复制一套简化实现。输出可直接复制的交接提示，并暂停所有依赖任务。提示统一使用“请调用 `<skill-name>`”，不维护不同平台的命令语法。

`build-agents-md` 的交接正文至少使用以下结构，并替换真实路径与任务：

```text
请调用 build-agents-md，继续完成 <项目绝对路径> 中 <TASK-ID> 的项目指令任务；依据仓库已验证的命令更新 AGENTS.md 和 CLAUDE.md，运行 `validate_agents_md.py --strict`，并返回验证结果。
```

其他配套 Skill 沿用同一通用调用范式，并包含目标、权威输入、允许与禁止范围、确认门禁、验证要求、返回格式和恢复条件，不能只写“请运行某 Skill”。

## 项目指令阻断边界

以下已证实问题阻断功能开发或最终交付：

- 根 `AGENTS.md` 缺失，或必要的局部指令缺失；
- `CLAUDE.md` 缺失、断链、目标错误或不再是单一来源入口；
- 构建、启动、测试命令实际失败且原因是文档失效；
- 目录职责、禁止修改区、安全规则或平台行为与最终项目冲突；
- 指令包含秘密、危险操作或互相冲突的要求。

纯文案精简、非关键背景不足、尚未证实的潜在过时和未来维护建议不阻断交付。不要借最终复查静默润色或整体重写项目指令。
