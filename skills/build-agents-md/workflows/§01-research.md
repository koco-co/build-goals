# §01 研究目标仓库

## 目标

在写任何正文前建立可追溯的项目事实集，并识别现有工作是否与本次替换重叠。

## 读取顺序

1. 确认目标根目录、Git 根目录、当前分支、工作区状态和已跟踪的符号链接。
2. 完整读取根目录及所有候选子树中的 `AGENTS.md`、`CLAUDE.md`；检查普通文件、符号链接、导入文件和潜在断链。
3. 读取 README、Manifest、包管理配置、任务脚本、CI、主要入口和已有开发文档。
4. 使用目录树和搜索定位语言、框架、工作区边界、生成物、测试位置及平台适配文件。
5. 对候选命令追溯到实际脚本或配置，不根据通用习惯猜测。

优先使用 `git status --short`、`git ls-files`、`find` 或 `rg --files`、`git diff -- AGENTS.md CLAUDE.md` 等只读检查。不要在研究阶段安装依赖或运行会改写仓库的工具。

## 事实表

为拟写内容记录：

- 事实或规则；
- 仓库证据位置；
- 适用作用域；
- 若写成命令，其验证状态；
- 若来自旧指令，保留、泛化、下沉或移除的理由。

对无法证实但会显著改变结果的信息，才向用户提问。安全、可从仓库确定的默认项直接形成预览，不把探索责任转给用户。

## 嵌套边界判定

列出候选子树，并按 `rules/content-admission.md` 的嵌套准入规则逐一判断。无独立差异时只保留根文件；有差异时，拟写增量规则而非复制根内容。

## 完成门槛

- 现有指令与用户未提交修改均已识别。
- 主要目录、真实命令、硬性不变量和验证入口均有证据。
- 所有拟建嵌套文件都有明确理由。
- 需要迁移或移除的 Claude 专有内容没有遗漏。
