# PRD 语义与场景验收清单

## 1. 事实与确认

- [ ] 所有产品结论都能追溯到实际产品行为、现有产品材料、用户确认或用户已采纳的外部实践。
- [ ] 已有项目的当前行为和目标需求明确分区，没有把代码推断当成产品意图。
- [ ] 用户已经确认全部产品决策，文档没有未决、假设、开放或阻塞内容。
- [ ] 此前 `shape-idea` 的确认结论得到复用，没有重复提问；缺失调研只补缺失部分。

## 2. 调研

- [ ] 至少检查 2 个竞品、2 个活跃开源项目和适用官方规范。
- [ ] 每个来源都是可复核的一手 URL，并记录真实访问日期和具体借鉴点。
- [ ] 已检查开源项目近期维护状态，没有用停止维护的实现代表当前最佳实践。
- [ ] 外部实践只作为候选方案，进入 PRD 的每个重要设计都已获用户确认。
- [ ] 没有复制外部文案、代码或其他受版权保护内容。

## 3. 产品覆盖

- [ ] 产品作用、目标用户、角色、范围边界和成功标准足以解释功能价值。
- [ ] 功能地图覆盖所有用户、管理员和运营角色可见的产品界面、入口与操作流程。
- [ ] 登录引导、设置、权限、搜索筛选、导入导出、通知和命令入口按实际适用性检查完毕。
- [ ] 每个跨功能用户旅程都能从入口走到明确完成或退出结果。
- [ ] 已安全运行的产品流程与真实状态、字段和文案一致；未运行部分使用的替代证据已明确确认。

## 4. 逐功能质量

- [ ] 每个功能编号唯一、稳定，并与功能地图对应。
- [ ] 每个功能都有作用、角色、入口、前置条件、输入、流程、状态文案、输出、边界恢复、质量要求、依据和验收标准。
- [ ] 用户预输入表格包含格式、范围、校验及正确与错误示例。
- [ ] 期望输出表格包含呈现形式、触发条件、状态、后续动作和完整示例。
- [ ] 加载、空状态、成功、失败、权限不足、取消、危险操作和恢复路径按适用性覆盖。
- [ ] 所有用户可见文案均为可直接使用的最终文本，并注明出现条件和下一步动作。

## 5. 验收与产品边界

- [ ] 每个主流程和适用分支都有对应的 Given/When/Then 验收标准。
- [ ] 验收结果只描述用户可观察行为，不依赖内部函数、数据库或服务状态。
- [ ] 产品质量要求可验证，但不规定技术实现方式。
- [ ] 文档不包含架构、技术栈、数据库、API、部署、工程任务、商业计划、预算、排期或组织分工。
- [ ] 最终目标只有 `docs/PRD需求文档.md`，没有额外备份、调研报告或第二份 PRD。
