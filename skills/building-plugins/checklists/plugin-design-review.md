# Plugin 设计落实检查

## 范围

- [ ] 每个已确认目标都有对应实现。
- [ ] 非目标没有被意外纳入。
- [ ] 变更没有越过用户确认的路径、平台和权限。
- [ ] 提交、推送、发布与删除均有独立授权。

## 架构

- [ ] Plugin 形态与用户目标一致。
- [ ] Skill、Agent、Hook、MCP、UI、脚本和 Manifest 职责清楚。
- [ ] 没有空目录、空文件和未来占位。
- [ ] 双平台共用内容只有一个规范源。
- [ ] 平台差异没有扩散到核心工作流。
- [ ] 所有软链接相对、有效且位于 Plugin 根目录内。

## Skills

- [ ] 每个 Skill 均符合 `building-skills` 规范。
- [ ] 新建或升级 Skill 已完成受控委派。
- [ ] `prompts/` 文件使用 `*.agent.md`。
- [ ] 显式与隐式调用策略符合设计。

## 平台

- [ ] Claude Code Manifest 路径与组件位置正确。
- [ ] Codex Manifest 与 Marketplace 路径正确。
- [ ] 两端名称、版本和共享组件一致。
- [ ] 无法等价实现的能力已明确降级。

## 验收

- [ ] 机械检查、语义验收和真实客户端测试分开记录。
- [ ] 正向、负向和失败路径均有结果。
- [ ] 未运行平台没有被描述为已通过。
