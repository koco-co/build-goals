# 路由分支示例

以下是行为 few-shot，不是固定版本、路径或路线答案。示例使用可触发模型直接调用的自然语言；用户也可以写成 Codex `$obsidian-learn-topic ...` 或 Claude `/obsidian-learn-topic ...`。运行时必须重新调研。

## 宽泛语言主题

用户：`我想系统学习 Python`

正确行为：

1. 把用户视为零基础教学对象。
2. 先询问可验证成果，例如自动化、数据处理或后端项目。
3. 调研当前受维护版本并提出推荐，不让用户在 Python 2 与多个 Python 3 版本中盲选。
4. 审计知识库已有 Python 内容和前置环境，再规划路径。

## 多语言绑定框架

用户：`我想学习 Playwright，目标是独立维护 E2E 测试`

正确行为：

1. 调研当前官方绑定和测试运行器。
2. 检查知识库中 JavaScript/TypeScript、Python、异步、包管理和测试基础。
3. 根据目标与证据推荐一个绑定，说明替代项代价，只等待这一项确认。
4. 将真正必需的语言能力设为硬前置；可在首章补齐的内容不阻断。

## 硬前置缺失

用户想学习框架，但最低语言与运行时能力既无有效文档，也未通过测验。

正确行为：停止主主题，不创建它的路线。给出前置主题、最低成果、可直接发送的启动指令，以及完成后的恢复指令。不得自动递归调用自身。

## 开源仓库

用户：`我想系统读懂 <owner/repo> 并能贡献一个修复`

正确行为：

1. 进入独立仓库分支，规范化 GitHub URL，锁定默认分支、目标 ref、完整 Commit、许可证和核验日期。
2. 固定使用项目概述、运行基线、架构地图、核心调用链、质量体系、Issue/PR 考古、最小修复、拓展、复习贡献九阶段；只在阶段内细分。
3. 建一份全局地图，但只选择一条核心调用链作为主切片，不按目录逐文件漫游。
4. 源码放在 Vault 外；已有 checkout 先审计 dirty/HEAD，否则使用隔离 detached Commit 环境。
5. README 只能作为入口，不能替代实际源码与测试检查。只有真实最小 Patch 和相关测试通过才完成毕业；commit、push、Issue/PR 另行授权。

失败边界：缺许可证时只读学习仍可继续，但 Patch 毕业阻断；上游变化只读报告，不自动更新本地环境。

## 只说继续

用户：`继续学习`

正确行为：从 Base 查询学习中主题。只有一个时恢复；多个时一次只询问选择哪一个；没有时询问主题。不得只凭当前聊天猜测。

## 普通代码型单元

用户正在学习 Python 函数，并进入“实现一个带边界检查的转换函数”单元。

正确行为：

1. 进入普通代码练习分支，只设计一个必做核心练习和最多两个可选挑战。
2. 完整公开 starter、核心测试、argv、通过标准、评分规则和三级提示；不先给完整解法。
3. 推荐一个 Vault 外工作区位置，但必须由用户提供并最终确认既有根路径；模型不创建根路径。
4. 用户真实尝试后，再确认精确命令合同并运行；把 append-only attempt 摘要写回笔记。
5. 绿灯后仍要求用户解释关键实现与边界；模型代写结果不算独立掌握证据。

失败边界：隐藏测试、未授权命令、越界写入、覆盖旧 attempt 或未尝试就给完整解答都必须停止。

## 相似内容

发现已有笔记时，先比较版本、来源、目录、出链和反向链接。准确内容用 Wikilink 复用；迁移、合并、归档或删除只输出动作预览，等待独立逐项确认。
