# 内容审查清单

本清单检查 Skill 是否正确、完整地实现已确认需求。措辞润色不属于本清单；如果表达问题导致行为含义不确定，则按内容问题处理。

## 需求与范围

- [ ] Skill 解决的是用户真实问题，而不是关键词表面匹配。
- [ ] 目标、非目标和完成标准彼此一致。
- [ ] 每个已确认目标都有对应行为或产物。
- [ ] 没有引入未确认的行为、权限或副作用。
- [ ] 已知事实、合理推断和未知项被清楚区分。

## 路由与流程

- [ ] 每类输入都能进入唯一分支，不属于本 Skill 的任务有退出方式。
- [ ] 步骤包含执行所需的条件、动作、结果和完成证据。
- [ ] 已知信息不会重复询问，可自行查明的事实不会转问用户。
- [ ] 失败、无法继续和用户取消都有明确结果。
- [ ] 按需读取关系不会遗漏关键规则。

## Frontmatter 与平台

- [ ] 已根据当前 Skill 提供的 Frontmatter 设计规则形成字段决策矩阵。
- [ ] 每个可选字段都有真实需求和目标平台依据。
- [ ] 调用策略、正文触发语义和 Codex 适配彼此一致。
- [ ] `compatibility` 只描述硬性环境要求；没有要求时已省略。
- [ ] 平台专属字段不会进入不支持它的安装副本。

## 安全与验证

- [ ] Guardrails 对应真实的数据、权限、接口或外部副作用风险。
- [ ] 设计确认与执行、提交、推送、发布授权被明确区分。
- [ ] 静态检查、场景验证和真实平台验证没有互相替代。
- [ ] “已验证”均能追溯到命令、文件、测试或真实结果。
- [ ] 未验证和阻塞内容已准确标记。

## 完成结果

- [ ] 内容正确性和完整性达到可进入文案审查的状态。
- [ ] 尚存歧义已作为内容问题解决，没有留给文案审查猜测。
