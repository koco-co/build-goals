# Plugin 设计落实检查

## 范围

- [ ] 每项组件、分支、兜底、兼容、校验、权限控制和提示词都有用户需求、仓库事实、平台契约、可复现缺陷或明确安全要求依据。
- [ ] 每个已确认目标都有对应实现。
- [ ] 非目标没有被意外纳入。
- [ ] 变更没有越过用户确认的路径、平台和权限。
- [ ] 提交、推送、发布与删除均有独立授权。

## 架构

- [ ] Plugin 形态与用户目标一致。
- [ ] Skill、Agent、Hook、MCP、UI、脚本和 Manifest 职责清楚。
- [ ] 没有空目录、空文件和未来占位。
- [ ] 各平台共用内容只有一个规范源。
- [ ] 平台差异没有扩散到核心工作流。
- [ ] 跨 Skill 运行依赖使用普通镜像，已声明规范源，并已确认镜像内容与规范源一致。
- [ ] 保留的必要软链接使用相对路径、目标有效，且解析后仍位于 Plugin 根目录内。

## 技能

- [ ] 每个 Skill 均符合 `build-skill` 规范。
- [ ] 新建或升级 Skill 的任务已交给 `build-skill`，并由原流程统筹。
- [ ] `prompts/` 文件使用 `*.agent.md`。
- [ ] 每个 Skill 的调用权限由平台配置控制；允许模型调用时，触发条件和排除条件优先写在跨平台 `description` 中。
- [ ] 每个 Skill 都有 Frontmatter 字段决策矩阵；`compatibility` 只描述硬性环境要求。
- [ ] 新建、整体重构或改变 Skill 触发、Frontmatter、权限与平台行为时已安排独立 Reviewer。

## 平台

- [ ] Claude Code Manifest 路径与组件位置正确。
- [ ] Codex Manifest 与 Marketplace 路径正确。
- [ ] ZCode Manifest 路径正确。
- [ ] 三份 Manifest 的名称、版本和共享组件一致。
- [ ] 已证实存在平台差异时，无法等价实现的能力已明确处理。

## 验收

- [ ] 静态检查、内容审查和真实客户端测试分开记录。
- [ ] 已确认行为、已声明契约和可复现缺陷均有结果；没有为假想风险制造负向或失败路径。
- [ ] 未运行平台没有被描述为已通过。
