# §05 交付

## 结果优先

先说明最终在哪些目录建立了指令、正文是否统一维护、验证是否通过。随后给出文件链接和必要的复现命令。

## 必须报告

- 新增、整体替换、删除和导入文件；
- 每个嵌套文件的存在理由；
- 旧 Claude 专有规则如何泛化、保留或经确认移除；
- 实际执行的命令与结果；
- “来源已确认、运行未验证”的命令及原因；
- 未做的真实 Claude Code/Codex 加载验证，以及其他无法完成的内容和原因；
- 明确未创建的项目文档、lint、CI 或 harness。

不要把校验器 PASS 扩大为“项目完全正确”或“两个客户端已验收”。

## 后续动作确认

先判断本次是独立调用，还是由 `audit-agent-setup` 等上层 Skill 调用。

### 受控调用（由上层 Skill 统筹）

不重复询问 commit、push、发布、部署或本地 Plugin 更新，也不自行执行。向上层返回：

- 修改内容与文件操作；
- 完整正文的确认依据；
- 静态校验和真实命令的验证证据；
- 未验证项；
- 恢复条件，以及是否允许继续其他后续任务。

发现新的产品、架构、公开接口或范围决策时，返回上层暂停处理，不自行扩大任务。

### 独立调用

实现和验证全部结束后，判断以下动作对当前仓库是否适用：

- commit；
- push；
- 更新本地 Claude Code Plugin；
- 更新本地 Codex Plugin。

只把当前仓库需要的操作放进一次确认问题，并允许用户逐项授权。未得到明确确认前不得执行；确认 commit 不等于确认 push，确认一个客户端更新也不等于确认另一个。

若用户暂不授权，交付仍然完成，保留清晰的工作区状态和建议提交说明即可。
