# 教程样例：给 API 增加可替换的依赖

> [!question] 真实问题
> 一个 HTTP 处理函数直接创建数据库客户端，测试不得不连接真实数据库。怎样把这项依赖替换成测试替身，同时保留一次完整请求？

## 贯穿案例

先固定一条 `GET /orders/{id}` 请求：输入订单 ID，输出订单摘要；不存在时返回明确的未找到结果。示例展示应用入口、依赖提供函数、处理函数和一个公开测试，读者可以复制为最小项目并看到预期响应。

## 机制与步骤

先画出“请求 → 依赖解析 → 处理函数 → 响应”的调用链，再逐步把直接构造改为参数注入。每一步都包含完整代码、运行命令和预期结果，而不是只展示关键两行。

## 失败边界

- 替身的接口与真实客户端漂移时，测试绿灯不能证明生产实现可用。
- 依赖生命周期选错时，可能在一次请求内重复创建昂贵连接。
- 覆盖测试只证明替换生效，不证明数据库事务语义。

## 独立证据

学习者新增第二种存储实现并替换依赖，运行公开测试，再解释依赖何时创建和释放。该证据属于 `tutorial-reproduction`；照抄原例不够。
