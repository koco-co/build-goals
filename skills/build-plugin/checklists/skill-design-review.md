# 设计落实检查清单

本清单用于比较“已确认设计”和“最终实现”，不替代静态校验。

## 目标与范围

- [ ] 每项行为、分支、兜底、兼容、校验、权限控制和提示词都有用户需求、仓库事实、平台契约、可复现缺陷或明确安全要求依据。
- [ ] 每个已确认目标都有对应实现或明确证据。
- [ ] 每个明确非目标都没有被意外纳入。
- [ ] 变更没有越过用户确认的路径和行为范围。
- [ ] 提交、推送、发布和破坏性操作均有独立授权。

## 路由与流程

- [ ] 目标能用一句话说明最终结果。
- [ ] 每个独立输入都能路由到唯一分支。
- [ ] 相邻但不属于本 Skill 的任务有明确退出方式。
- [ ] 每个阶段都有完成条件。
- [ ] 已确认或可复现的失败、无法继续和用户取消场景有明确结果；没有为假想场景增加流程。
- [ ] 用户确认前保持只读。

## 架构

- [ ] 每个目录和文件都有单一、必要职责。
- [ ] 没有空目录、空文件或未来占位内容。
- [ ] `SKILL.md` 保持主流程清晰，细节按需读取。
- [ ] `SKILL.md` 只保留目标、路由/退出、执行顺序和必要红线；每个额外状态、分支、文件、示例或校验都有明确依据。
- [ ] 模板、示例、规则、工作流和按需读取索引没有重复职责。
- [ ] 能够按确定规则执行的内容已交给 CLI、脚本或测试。
- [ ] 每次事件必须自动发生的内容已放入 Hooks 或 CI。
- [ ] 项目级 Skill 复用了项目已有能力，没有复制业务实现。
- [ ] 放入 `.agents/scripts/` 的脚本已有至少两个真实 Skill 调用方，共享契约一致，并且共享目录会随项目或整体安装包交付。
- [ ] 无法保证共享目录存在的独立 Skill 保持自包含，没有失效的项目根目录脚本调用。
- [ ] 新增脚本优先采用无需第三方依赖的 MJS 或 Shell；采用 Python 等语言时有任务依据，并明确运行时、依赖和验证命令。

## 平台适配

- [ ] 核心工作流只有一个规范源。
- [ ] Frontmatter 只记录必填、实际使用或用户指定审查的字段，每个可选字段都有事实依据。
- [ ] 平台专属字段没有写入其他平台配置。
- [ ] 调用权限由平台配置控制；允许模型调用时，`description` 或 `when_to_use` 已写清触发条件和排除条件。
- [ ] `compatibility` 只描述硬性环境要求；没有要求时已省略。
- [ ] 安装路径、权限和依赖符合目标平台当前契约。
- [ ] 已证实存在平台差异时，无法等价适配的能力已明确处理。

## 验证设计

- [ ] 静态检查、内容审查、文案审查、内容回归和真实场景验证彼此分离。
- [ ] 适用的重要变更已完成独立 Reviewer 审查；未完成时如实标记。
- [ ] 已确认行为、已声明契约和可复现缺陷有对应测试；没有为假想风险制造负向或失败测试。
- [ ] 验证命令可复现，失败返回非零退出码。
- [ ] 未验证内容和无法完成的内容不会被描述为已通过。
